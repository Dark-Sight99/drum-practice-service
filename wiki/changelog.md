## v1.2 — 모바일 성능·재생 엔진 개선 (2026-10-30~2026-10-31, 진행 중 — 아직 태그 없음)
Phase 6으로 시작(의뢰인 결정: "1.2버전으로 모바일개선에 집중") — 목표는 iOS Safari 연습 화면 fps(Q-33, 60fps 목표 미달) 해결. 조사가 깊어지며 원인이 "비효율적 렌더링"이 아니라 "오디오 재생 아키텍처 자체"(`<audio>` 엘리먼트 기반)로 좁혀졌고, 결국 재생 엔진 전체 교체(T6-11)로 이어짐 — 그 과정에서 편집화면 기능 개선도 다수 포함됨.

- **모바일 fps 원인 규명**(T6-1~T6-10): 안전한 렌더 루프 최적화(T6-1)만으론 미해결 → 실기기 단계적 이분탐색으로 "4개 오디오 트랙 동시 디코딩"(T6-2)→"서버/iOS 샘플레이트 불일치"(T6-4/T6-5)→"iOS 전용 resync() seek"(T6-9)로 원인을 좁혀감. 음악 3스템(베이스/보컬/기타) 사전 믹스로 동시 스트림 4→2개 축소(T6-3). resync()를 playbackRate 소프트 보정으로 바꾸는 시도(T6-10)는 음원이 끊겨 되돌림 — **진짜 해법은 재생 엔진 교체임을 확인**
- **재생 엔진 전면 교체**(T6-11): 스템 재생을 `<audio>` 엘리먼트에서 `Tone.Player`(AudioBufferSourceNode)로 전환, 원인이었던 `resync()`를 완전히 제거(Transport 네이티브 이벤트로 직접 동기화) — **iOS 실기기 fps 60 달성 확인, Q-33 해소**
- **서버 음정유지 배속 변환**(T6-11 Step3): 실시간 피치 보정 대신 서버가 ffmpeg `atempo`로 미리 변환+캐싱(요청 내 동기 처리, 실측 최대 5.5초)
- **iOS 메모리 강제종료 완화**(T6-11): 실기기에서 BPM 반복 변경 시 OOM으로 탭이 강제 재시작되는 문제 — 스템 재로딩 지연(150ms), iOS 전용 배속 하한 상향(50%→70%), 음악 스템 모노 저장(스테레오 대비 버퍼 25%↓)로 완화(완전 해결 아님, 의뢰인 승인으로 "완화"로 종결)
- **편집화면 BPM "적용" 버튼**(T6-11): 슬라이더/숫자 조절이 바로 반영되지 않고 "적용" 버튼을 눌러야 커밋 — 재로딩 빈도 자체를 줄이는 메모리 완화책 겸 실수 방지(의뢰인 요청)
- **라이브러리 "최근 사용한 곡" 최상단 정렬**(REQ-07, 의뢰인 요청): 연습/편집 화면에서 연 곡이 라이브러리 맨 위로
- **기타 버그 수정**: 연습↔편집 화면 BPM 단방향 동기화, `handSource: null` 저장 실패 버그(Q-47), 편집화면 믹서 UI 깜빡임, BPM 세자리 숫자 잘림
- **main 병합 전 Codex 읽기전용 검수**(모드A, 전체 branch 62커밋 첫 리뷰): 믹스 클리핑 위험(스템·신스드럼·메트로놈이 각자 리미터를 걸고 있었지만 셋이 합쳐지는 최종 레벨은 안 묶여있던 문제) 발견·수정(공유 Limiter 도입), 경계 배속(permille)에서 서버 500 에러 발견·수정, 그 수정이 만든 스템-신스 드리프트까지 재검수로 발견·수정 — 전부 APPROVE 후 병합(2026-10-31)
