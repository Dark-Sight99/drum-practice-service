## v1.1 — 편집 기능 개선 (2026-10-29~2026-10-31, 태그 미정)

- **Q-43 다운비트 자동 보정**(T3-72): 음원 채보 시 틱 0(마디 시작)이 실제 드럼 첫 타격과 어긋나던 위상 오프셋(~0.28초)을 자동 재앵커로 보정 — 편집기·연습 화면 둘 다 영향받지만 채보 정확도 문제라 편집 쪽에 포함
- **편집기 UX 다듬기**(T3-73~T3-81, 실사용 피드백 기반):
  - 노트 모양을 원→네모, 위치 기준을 중앙→왼쪽(이른 시간) 모서리로 — 연습 화면과 통일
  - 재생 중 그리드 자동 스크롤, 재생 중 편집(추가/선택/드래그) 잠금
  - 노트 추가 시 인접 노트에 스냅, 화살표 이동을 절대격자 대신 상대이동(+항상 1/16박 고정)으로 변경
  - 노트 클릭 시 포커스 부여(키보드 이동 복구), 손/발 수동 지정 버튼 제거(자동 추천만 사용)
- **편집화면 BPM "적용" 버튼**(T6-11, 의뢰인 요청): 슬라이더/숫자 조절이 바로 반영되지 않고 "적용" 버튼을 눌러야 커밋 — 실수로 BPM이 바뀌는 걸 방지(부수 효과로 스템 재로딩 빈도도 줄어 iOS 메모리 완화에도 기여, v1.2 참고)
- **편집화면 믹서 UI 깜빡임 수정**(T6-11): 스템 재로딩 중 원곡드럼·음악 슬라이더가 DOM에서 빠졌다 다시 생기던 버그
- **BPM 세자리 숫자 잘림 수정**(T6-11): "130" 같은 세 자리 BPM이 입력칸에서 "13"으로 잘려 보이던 버그
- **`handSource: null` 저장 실패 버그 수정**(Q-47): 자동 채보된 곡은 전부 편집 화면에서 저장 자체가 항상 막혀 있던 버그
- **연습→편집 화면 BPM 동기화**(단방향): 연습 화면에서 바꾼 BPM이 편집 화면에 그대로 반영(편집 화면의 변경은 거꾸로 전파 안 됨)
- **라이브러리 "최근 사용한 곡" 최상단 정렬**(REQ-07, 의뢰인 요청): 연습/편집 화면에서 연 곡이 라이브러리 맨 위로 — 편집 화면 진입 경로와 맞물려 함께 기록

## v1.2 — 모바일 사용 환경 개선 (2026-10-30~2026-10-31, 진행 중 — 아직 태그 없음)
Phase 6으로 시작(의뢰인 결정: "1.2버전으로 모바일개선에 집중") — 목표는 iOS Safari 연습 화면 fps(Q-33, 60fps 목표 미달) 해결. 조사가 깊어지며 원인이 "비효율적 렌더링"이 아니라 "오디오 재생 아키텍처 자체"(`<audio>` 엘리먼트 기반)로 좁혀졌고, 재생 엔진 전체 교체(T6-11)로 이어짐.

- **모바일 fps 원인 규명**(T6-1~T6-10): 안전한 렌더 루프 최적화(T6-1)만으론 미해결 → 실기기 단계적 이분탐색으로 "4개 오디오 트랙 동시 디코딩"(T6-2)→"서버/iOS 샘플레이트 불일치"(T6-4/T6-5)→"iOS 전용 resync() seek"(T6-9)로 원인을 좁혀감. 음악 3스템(베이스/보컬/기타) 사전 믹스로 동시 스트림 4→2개 축소(T6-3). resync()를 playbackRate 소프트 보정으로 바꾸는 시도(T6-10)는 음원이 끊겨 되돌림 — **진짜 해법은 재생 엔진 교체임을 확인**
- **폰 가로모드 레인-재생버튼 겹침 버그 수정**(T5-1)
- **재생 엔진 전면 교체**(T6-11): 스템 재생을 `<audio>` 엘리먼트에서 `Tone.Player`(AudioBufferSourceNode)로 전환, 원인이었던 `resync()`를 완전히 제거(Transport 네이티브 이벤트로 직접 동기화) — **iOS 실기기 fps 60 달성 확인, Q-33 해소**
- **서버 음정유지 배속 변환**(T6-11 Step3): 클라이언트 측 실시간 피치 보정 라이브러리(AudioWorklet 기반)가 iOS에서 간헐적으로 밀리는 버그가 있어, 서버가 ffmpeg `atempo`로 미리 변환+캐싱하는 방식으로 전환(요청 내 동기 처리, 실측 최대 5.5초)
- **iOS 메모리 강제종료 완화**(T6-11): 실기기에서 BPM 반복 변경 시 OOM으로 탭이 강제 재시작되는 문제 — 스템 재로딩 지연(150ms), iOS 전용 배속 하한 상향(50%→70%), 음악 스템 모노 저장(스테레오 대비 버퍼 25%↓)로 완화(완전 해결 아님, 의뢰인 승인으로 "완화"로 종결)
- **main 병합 전 Codex 읽기전용 검수**(모드A, 전체 branch 62커밋 첫 리뷰) — 재생 엔진 전체 교체에 딸려온 안정성 문제 3건 발견·수정:
  - 믹스 클리핑 위험: 스템·신스드럼·메트로놈이 각자 리미터를 걸고 있었지만 셋이 합쳐지는 최종 레벨은 안 묶여있던 문제 → 공유 Limiter 도입
  - 경계 배속(permille)에서 서버가 500 에러를 내던 버그(원곡 BPM이 정수가 아닌 곡 다수에서 실제 재현)
  - 위 수정이 만든 스템-신스 드리프트(재검수로 발견) — 곡 끝까지 최대 1초 이상 누적될 수 있었음
  - 전부 수정 후 APPROVE, 2026-10-31 main 병합
