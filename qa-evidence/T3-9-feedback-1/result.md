## 근거(REQ)

## 진단
`⟲ A-B 루프` 체크박스에 `disabled={isPlaying || isPaused}`가 남아 있어, 재생/일시정지 중엔 루프를 켤 수만 있고 끌 수 없었음. 이 제약은 T3-9 이전("루프 설정은 재생 시작 시점에 한 번만 적용되고, 재생 중 바꿔도 반영 안 됨")의 유산인데, T3-9가 `work/T3-9/plan.md` §6에 재생 중 루프 상태 변경을 살아있는 Tone.js Transport에 즉시 반영하는 `useEffect`를 신설하면서(모드A 검수까지 통과, "루프가 꺼질 때" 자동 정지 타이머 재구성 경로 포함) 이 제약의 전제가 이미 사라졌음에도 체크박스의 `disabled` 조건을 걷어내지 않아 남아 있던 버그.

## 변경 내용
- `app/web/src/features/practice/PracticeCanvas.tsx` — `⟲ A-B 루프` 체크박스의 `disabled={isPlaying || isPaused}` 제거(체크박스만; 마디 번호 입력칸 2개는 이번 요청 범위 밖이라 기존대로 재생 중 잠금 유지).

## 위험 분류
"오디오 타이밍·동기" 관련 로직 자체를 새로 만들지 않고, T3-9에서 이미 모드C 3라운드 + 모드A 2라운드로 검수받은 §6 live-reapply effect를 그대로 재사용하는 **순수 UI 잠금 해제**이므로 모드C 생략, 모드A만 진행(프로젝트 선례: T3-4-feedback-2/3, T3-8의 라벨/기본값/버튼 제거 변경과 동일 분류).

## 브라우저 수동 검증 (localhost:5173, huibigyocha 곡, 새 탭에서 콘솔 이력 초기화 후 확인)
1. **재생 중 끄기**: 재생 시작 → DOM에서 체크박스 `disabled: false` 확인(이전엔 `true`였을 상태) → "⏱ 여기서 시작"/"⏱ 여기까지"로 마디 7~11 루프 설정 → 체크박스 클릭해 끄기 → "⟲ 마디 N~M 반복 중" 표시가 즉시 사라짐 → 재생/정지 버튼 상태는 계속 "재생 중"(정지되지 않음) → 수 초 더 대기해도 조기 자동 정지 없이 재생 지속(§6 effect의 "루프 꺼질 때 자동 정지 타이머 재구성" 경로 — 이전엔 모드A가 "현재는 도달 불가"로 분류했던 코드가 이번에 실제로 실행되며 정상 동작 확인) → 콘솔 에러 0건.
2. **일시정지 중 끄기**(이전 세션에서 미완료였던 케이스): 일시정지 → "⏱ 여기서 시작" → "10초 ▶▶"로 위치 이동 → "⏱ 여기까지" → "⟲ 마디 25~30 반복 중" 표시 확인 → `window.setTimeout`/`clearTimeout`을 몽키패치해 호출 로그 확보 → 체크박스 클릭해 끄기 → **`setTimeout` 호출 0건, `clearTimeout` 호출 0건** (§6 effect의 `!isPaused` 분기—실시간 타이머를 새로 거는 경로—가 전혀 실행되지 않았다는 직접 증거. T3-6의 "일시정지 중엔 실시간으로 타이머가 흐르면 안 된다" 불변식을 지킴. 다만 `autoStopRemainingMsRef`가 이미 `null`이 아니었던 경우라 애초에 재계산 자체가 스킵됐을 가능성도 있어, "값만 갱신하고 타이머는 안 거는" 분기까지 직접 찍어 확인하진 못함 — 기능적으로는 재생 중 테스트와 동일 패턴이라 리스크 낮음으로 판단) → "⟲ 반복 중" 표시 사라짐, 재생/일시정지 버튼은 계속 "일시정지" 상태 유지 → "▶ 재생" 클릭해 재개 → 3초 대기, 콘솔 에러 0건.

## 결론
체크박스만 잠금 해제하는 최소 변경으로 의뢰인이 보고한 문제(루프를 풀고 계속 진행할 방법이 없음)가 해결됨. 재생 중·일시정지 중 두 경우 모두 "루프 끄기 → 재생 계속/일시정지 유지, 조기 정지나 콘솔 에러 없음"을 직접 확인. 기존에 검증된 T3-9 §6 메커니즘을 그대로 재사용했으므로 새로운 타이밍 버그 유입 가능성은 낮다고 판단.
