# T3-77 QA 증거

## 배경
의뢰인이 "HH랑 MT을 동시에 쳐야 하는데 어디 찍어야 할지 모르겠다", "1/16박 뒤에 치려면 어디다 찍어야 하냐"고 질문 — 기존 화살표 키 이동 기능(1/16씩 이동)을 보여줬더니, "새로 찍은 노트만 절대 격자에 맞추면 뭐하냐, 실제 연주(HH 등)는 그 격자에 안 맞춰져 있어서(T3-72/Q-43) 들어보면 같은 순간에 안 친다"고 정확히 지적 — 화살표 이동이 실제 기존 노트 기준이 아니라 "0틱 기준 이론상 격자"에 매번 다시 스냅되고 있었음.

## 구현
`app/web/src/features/editor/EditorScreen.tsx`:
1. **`handleRowClick`(클릭으로 노트 추가)**: 클릭 지점에서 가장 가까운 기존 노트(행 무관)가 현재 격자 한 칸의 절반 이내에 있으면, 그 노트의 실제 틱에 그대로 맞춰 찍음(기존엔 픽셀→틱 변환값을 그대로 썼음).
2. **`moveSelected`(화살표 키 이동)**: `snapTick()`(절대 0틱 기준 격자로 매번 재정렬)을 제거하고, 드래그 이동과 같은 방식(상대 이동)으로 변경.

## Codex 모드A 3라운드
- **1차 REQUEST_CHANGES(C-001, 필수)**: unitTicks가 정수가 아닌 격자(예: ppq=100의 8분음표 셋잇단, 33.333…)에서 "이미 반올림된 틱에 다시 더해 반올림"을 반복하면 오차가 누적(30번 누르면 10틱 차이) → **기준 틱 + 누른 횟수(정수)를 따로 추적**해 매번 "기준+N*격자폭"을 한 번만 반올림하도록 수정(`moveAnchorRef`). 회귀 테스트 추가(3번 눌러 150이 나와야 함, 수정 전엔 149).
- **2차 REQUEST_CHANGES(C-001, 필수)**: 틱 0에서 ←를 눌러 클램프된 뒤, 유효성 검사가 클램프를 또 적용해 "클램프됐다"는 사실 자체를 가려버려서, 바로 이어서 →를 눌러도 이동이 소실(0에 그대로 머묾)되는 경계 버그 발견 → **클램프가 실제로 일어난 순간을 감지해 그 자리를 새 기준점으로 재설정**하도록 수정. 격자 단위 자체도 기준점에 저장해(C-002, 권장) 격자 설정을 바꾼 경우 우연히 틱이 같아도 재설정되게 함. 회귀 테스트 추가(틱0에서 ←→ 누르면 240이 나와야 함, 수정 전엔 0에 고착).
- **3차 APPROVE**: 위 전부 반영 확인, 추가 지적 없음.
