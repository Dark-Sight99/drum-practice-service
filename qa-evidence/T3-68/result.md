T3-67에서 "격자 선에만 찍힌다"는 재지적에 대해 두 가지를 직접 여쭤봤고,
답을 받았다:
1. "클릭/드래그로 노트를 놓을 때, 격자에 관계없이 정확히 누른 위치에

2. "노트를 선택하면 그 위에 '선택됨' 패널이 나타나면서 그리드 전체가

## 구현

### 1. 클릭·드래그 자유 배치(격자 무시)(REQ-03)
`pxToSnappedTick`(바닥 함수 스냅)을 `pxToTick`(스냅 없이 클릭한 픽셀을
그대로 틱으로 환산, 정수로만 반올림)으로 교체. 드래그의 `mousemove`
처리도 같은 방식(`floorSnapTick` 호출 제거, 델타를 그대로 정수 틱으로
반올림)으로 통일. 격자선 자체(T3-65)는 그대로 둔다 — 몇 분음표
간격인지 눈으로 가늠하는 보기용 기준선으로는 여전히 유용하고, 의뢰인도
"격자에 관계없이"라고만 했지 격자선을 지워달라고 하진 않았다.
`snapTick()`(grid.ts, 반올림)·`floorSnapTick`은 더 안 쓰여 `floorSnapTick`
삭제 — `snapTick()`은 화살표 키 이동(`moveSelected`)이 여전히 쓰므로
grid.ts에서 안 지웠다(화살표 키로 "몇 칸 이동"은 격자 단위 개념이라
스냅이 자연스럽다고 판단, 의뢰인 질문도 "클릭/드래그" 한정이었음).

### 2. 선택 시 그리드가 밀리는 문제 고정(T3-67에서 발견)
노트를 선택하면 "선택됨: ... 약 중 강 ... 삭제" 패널이 그리드 **위에**
나타나며 그리드 전체를 아래로 밀던 것을, 그 패널을 감싸는 컨테이너에
`minHeight: 96`(선택 패널의 가장 넓은 경우 — HH 선택 시 닫힘/열림 버튼
2개 추가로 줄바꿈되는 경우를 실제로 띄워 측정한 86px에 여유를 둔 값)을
줘서 선택 여부와 무관하게 항상 같은 공간을 예약하도록 고쳤다.

**시도했다 되돌린 방법**: 처음엔 "선택 패널과 똑같은 내용을 안 보이게
숨겨서 자동으로 꼭 맞는 공간을 재는" 방식(`visibility: hidden`인 복제
패널)을 시도했는데, 숨긴 텍스트도 DOM에는 그대로 남아 있어(`visibility:
hidden`은 `display: none`과 달리 텍스트 검색엔 걸림) 테스트의
`screen.getByText('선택됨: HH')`·`getByRole('button', {name: '열림'})`
같은 쿼리가 "여러 개 찾음" 에러를 냈다 — 더 단순하고 테스트와 안 부딪히는
고정값(`minHeight`)으로 바꿨다.

## Codex 모드A 검수(읽기 전용)
- 대상: `task/T3-68-editor-free-placement-and-layout-stability` vs `main`.
- **1차 — APPROVE(지적 없음)**. `floorSnapTick`·`pxToSnappedTick`
  잔여 참조 없음, 클릭·드래그 결과가 항상 0 이상 정수 틱으로 반올림됨,

  요구하지 않아 자유 배치와 충돌 없음, 테스트 기대값이 실제 상수

  선택 패널이 일반 흐름 안에 정상 렌더링됨을 확인. 참고(지적은 아님) —
  래퍼의 `position: relative`가 이제 불필요(되돌린 접근법의 잔재) — 바로
  반영해 제거. `minHeight: 96`보다 패널이 커지는 아주 좁은 화면에서는
  예약 공간을 넘어설 수 있으나 잘림·겹침 없이 그리드가 추가로 조금
  밀리는 정도의 레이아웃 한계일 뿐.
