# T3-13 QA 결과

## 근거(REQ)
- REQ-04 "일시정지/이어재생"(UI 버튼 이름 변경).
- 의뢰인 요청(이미지 2장 첨부): "재생하고 일시정지를 같은 버튼으로 써서 두 기능이 번갈아가면서 적용되게 할 수 없을까. 정지라는 단어대신 리셋으로 바꾸고. 이미지처럼 하나의 버튼으로 시작 일시정지 가능하게 양옆에 10초 뒤로 앞으로 하고."

## 변경 내용 (`app/web/src/features/practice/PracticeCanvas.tsx`만 수정)
- "▶ 재생"/"⏸ 일시정지" 두 버튼을 `isPlaying` 조건부 렌더링으로 하나의 토글 버튼으로 통합(표준 미디어 플레이어 패턴). 기존 `handlePlay()`/`handlePause()` 함수는 전혀 안 건드림 — `handlePlay()`가 이미 `isPaused` 분기로 "정지 상태에서 시작"과 "일시정지 중 재개"를 둘 다 처리하므로, 토글 버튼이 꺼져 있을 때 누르면 자동으로 맞는 동작이 됨.
- "⏹ 정지" → "↺ 리셋"(이름만 변경, `handleStop` 핸들러·`disabled` 조건 그대로).
- 버튼 순서를 이미지와 같이 "◀◀10초 — 토글 — 10초▶▶ — 리셋"로 재배치(기존엔 재생/일시정지/정지 묶음과 ±10초 묶음이 별도 `<div>`였음, 지금은 하나로 통합).

## 위험 분류
순수 UI 재구성(조건부 렌더링·라벨·배치)이고 재생 제어 로직(`handlePlay`/`handlePause`/`handleStop`/`handleSeek`)은 전혀 안 건드림 — 모드C 생략, 모드A만 진행.

## 브라우저 수동 검증 (localhost:5174, huibigyocha 곡)
전체 흐름을 순서대로 확인: ① "▶ 재생" 클릭 → 토글이 "⏸ 일시정지"로 바뀌고 재생 시작, ◀◀10초/10초▶▶/리셋 버튼 활성화됨. ② "⏸ 일시정지" 클릭 → 토글이 다시 "▶ 재생"으로 바뀌고 일시정지(페이지 텍스트로 확인). ③ 그 "▶ 재생"을 다시 클릭 → 처음부터가 아니라 멈춘 지점부터 재개(토글이 "⏸ 일시정지"로 바뀜 — `handlePlay()`의 기존 `isPaused` 분기가 정상 작동함을 확인). ④ "↺ 리셋" 클릭 → 토글이 "▶ 재생"으로, 나머지 버튼은 비활성화(처음 상태로 복귀). 매 단계 콘솔 에러 0건.

## 결론
기존 재생 제어 로직을 전혀 안 건드리고 버튼 구성(조건부 렌더링 + 라벨 + 배치)만 바꾼 저위험 변경. 요청하신 3가지(토글 통합·리셋 이름·버튼 배치) 전부 반영, 실제 흐름(재생→일시정지→재개→리셋)을 브라우저로 직접 확인.
