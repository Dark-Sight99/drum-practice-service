# T3-54 결과

## 배경 (의뢰인 요청, 2026-10-29)
"서버렉이나 어떤 이유로 로딩이 길어졌을 때 스켈레톤 로딩 적용되었어?
... 다운로드 중 재생 버튼 이거 일부러 막아둔거니까. 다운로드 다
완료될때까지 스켈레톤로딩 넣어서 경험에 방해없게 하자고 한 거였음."
— 재생 버튼이 음원 트랙 다운로드 중 비활성화되는 기존 보호장치(T3-16
-feedback-7, 끊김 재현 이력 있어 의도적으로 막아둠)는 그대로 유지하되,
그 대기 시간 자체를 더 매끄럽게 느껴지도록 개선.

## 조사
코드 전수 확인 결과 스켈레톤/로딩 표시가 적용된 곳은 로그인 상태
확인(App.tsx)·라이브러리 목록 로딩(LibraryScreen)뿐이었고, 아래 두
지점은 전혀 표시가 없었음(이전 턴에 이미 보고):
1. 라이브러리에서 곡을 클릭해 연습 화면으로 넘어가는 순간
   (`handleOpen`의 `fetchSongDrumScore` 대기) — 버튼이 조용히
   비활성화되는 것 말고는 아무 표시 없음.
2. 연습 화면 재생 버튼이 `audioTracksLoading` 중 비활성화될 때 — 흐려진
   ▶ 아이콘 + 툴팁 텍스트뿐, "지금 실제로 뭔가 진행 중"이라는 느낌이
   약함.

## 구현
둘 다 "레이아웃 placeholder"가 아니라 "배경 작업이 진행 중"인 상황이라,
이미 업로드 화면("노트를 생성하는 중…")에서 쓰던
`components/Spinner.tsx`를 그대로 재사용(새 컴포넌트 안 만듦).
- `app/web/src/features/practice/PracticeCanvas.tsx` — 재생/일시정지
  토글 버튼에서, `audioTracksLoading`이 참이면 ▶ 아이콘 대신 `<Spinner
  size={22}/>`를 그린다. 버튼 자체는 여전히 `disabled`(보호장치
  유지) — 아이콘만 "정지된 화살표"에서 "도는 원"으로 바뀌어 대기
  중임이 더 분명해짐.
- `app/web/src/features/library/LibraryScreen.tsx` — 곡 제목 버튼
  (`isReady`인 곡)에 `openingId === song.id`일 때 `<Spinner size={16}/>`
  를 제목 앞에 추가. "편집" 버튼도 같은 `openingId`를 공유해 같이
  비활성화되므로, 제목의 스피너가 "이 곡의 데이터가 지금 로딩 중"임을
  (어느 버튼을 눌렀든) 공통으로 보여줌 — 별도 상태 추가 없이 기존 상태
  재사용.

## 테스트
- `npx tsc --noEmit`·`npx oxlint` — 에러 없음(기존 경고만).
- `npx vitest run` — 275/275 통과(조건부 아이콘/스피너 렌더링만 추가,
  기존 로직·상태 전이 무변경).

## 브라우저 수동 QA
로그인 세션이 없어(이전과 같은 이유) 실제 화면 대신, 같은 CSS를
그대로 가져온 격리 미리보기 페이지(Vite dev 서버 `public/` 아래 임시
파일 — 확인 후 즉시 삭제, 레포에 커밋 안 됨)로 두 상태를 렌더링해
스크린샷 확인:
1. 재생 버튼(흰색 원, 비활성화) 안에 22px 스피너 — 흰 배경 위에서
   어두운 링+파란 회전 구간이 또렷하게 보임.
2. 라이브러리 제목 버튼 앞 16px 스피너 — 제목 텍스트와 나란히 자연스럽게
   배치됨.
