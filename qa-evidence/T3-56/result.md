# T3-56 결과

## 배경 (의뢰인 요청, 2026-10-29)
"계정 생성기능도 있었으면 하는데 아이디비번찾기랑"

REQ-08(`intent/02-requirements.md`)는 2026-10-23에 이미 확정된 결정이다:
"대중 공개 아님, 비상업. 의뢰인 포함 소수 지인 최대 6명이 쓰는 비공개
서비스. 가입 화면 없음 — 관리자(의뢰인)가 계정을 직접 생성·정지." 이
결정 자체를 뒤집는(공개 회원가입) 건 범위 밖 작업이라 CLAUDE.md 절대
규칙 6에 따라 바로 만들지 않고, `AskUserQuestion`으로 두 가지를 먼저
확인했다:
1. 가입을 공개로 열지 / 관리자 전용 화면으로 둘지 → **관리자 전용**(REQ-08
   유지) 선택.
2. 비번 찾기를 이메일로 할지 / 관리자가 재설정해줄지 → **관리자가
   재설정**(이메일 발송 서비스 신규 가입 불필요) 선택.

백엔드 `POST /admin/users`(계정 생성)·`PATCH /admin/users/{id}`(정지)
API는 T1-3부터 이미 있었지만, 그걸 쓸 수 있는 화면이 프런트엔드에 전혀
없었다(관리자가 API를 직접 curl로 호출해야 했음) — 이번 작업은 그
화면과, 없던 "비밀번호 재설정"·"목록 조회" API를 추가.

## 구현

### 백엔드 (`app/server/api/admin.py`)
- `GET /admin/users` 신규 — 전체 계정 목록(`require_admin`). 화면의
  "아이디 찾기"를 겸한다 — 관리자가 등록된 아이디를 바로 볼 수 있음.
- `POST /admin/users/{id}/reset-password` 신규 — 이메일 없이 관리자가
  직접 새 비밀번호를 해시해 저장(`require_admin`). "비번 찾기" 요청에
  대한 답.
- 기존 `POST /admin/users`(생성)·`PATCH /admin/users/{id}`(정지)는
  무변경.

### 프런트엔드
- `app/web/src/api/admin.ts` 신규 — `listUsers`/`createUser`/
  `setUserActive`/`resetUserPassword`.
- `app/web/src/features/admin/AdminScreen.tsx` 신규 —
  - 상단 "새 계정 만들기" 폼(아이디·비밀번호·관리자 여부 체크박스).
  - 계정 목록(아이디, 관리자/정지됨 뱃지, 정지·정지해제 토글, 비밀번호
    재설정 버튼).
  - 비밀번호 재설정은 기존 `Modal` 재사용 — 새 비밀번호 한 칸 입력 후
    제출.
  - 성공 시 기존 `Toast` 재사용(업로드 완료 토스트와 같은 패턴).
  - 로딩/에러 상태는 기존 화면들과 같은 패턴(`error && <p role="alert">`,
    "불러오는 중…" 텍스트).
  - **안전장치**: 본인(로그인한 관리자 자신) 계정은 정지 버튼이
    비활성화됨 — Q-16(`intent/07-open-questions.md`, "의뢰인 혼자
    관리자인 전제") 상황에서 실수로 자기 자신을 정지시켜 잠기는 걸
    막는다. 의뢰인이 명시적으로 요청한 건 아니지만, 되돌릴 수 없는
    자기잠금 사고를 막는 작은 방어라 범위 안이라고 판단.
- `App.tsx` — `Screen` 타입에 `'admin'` 추가, `user.is_admin`·
  `user.id`를 `AdminScreen`/`LibraryScreen`에 전달.
- `LibraryScreen.tsx` — `isAdmin`/`onOpenAdmin` prop 추가(기존 호출부
  22곳이 안 깨지게 선택값+기본값 `false`로 둠). 관리자일 때만 헤더에
  "계정 관리" 버튼 노출.
