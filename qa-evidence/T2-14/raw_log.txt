===== 분석 데이터 획득(재현 방법, Codex 모드B 1·2·3차 지적 반영) =====
song2.json은 악보 데이터라 레포에 커밋하지 않는다(CLAUDE.md §5 data/ 커밋 금지
원칙과 같은 취지, T2-11/T2-12/T2-13에서도 동일하게 적용). 아래는 **이 세션에서
실제로 실행한 셸**(Git Bash — 이 레포의 모든 raw_log.txt가 T2-6부터 일관되게
bash 문법을 써왔고, 이번 T2-14까지 전부 이 Bash 도구로 실행함, Windows PowerShell
아님) 기준 재현 명령이다. 두 스크립트는 저장 경로를 첫 인자로 받도록 수정됨
(Codex 모드B 2차 지적 반영). **모드B 3차가 "스크립트가 qa-evidence/T2-14/에
있어 레포 루트에서 실행하면 못 찾는다"고 추가 지적** — 작업 디렉터리를
`qa-evidence/T2-14`로 명시해 반영:
  cd qa-evidence/T2-14
  curl -c cookies.txt -X POST "http://localhost:8000/auth/login" \
    -H "Content-Type: application/json" \
    -d "{\"username\":\"$QA_USER\",\"password\":\"$QA_PASS\"}"
  curl -b cookies.txt "http://localhost:8000/songs/2/drumscore" -o song2.json
  PYTHONIOENCODING=utf-8 python hh_spacing_analysis.py song2.json
  PYTHONIOENCODING=utf-8 python hh_interval_crosscheck.py song2.json
(위 두 python 명령에 `PYTHONIOENCODING=utf-8`이 꼭 필요함을 직접 재현해 확인했다
— 이 환경변수 없이 그대로 실행하면 Windows 콘솔 기본 인코딩[cp949]이 스크립트의
한글 출력 중 일부 문자[예: em dash "—"]를 인코딩하지 못해 `hh_interval_crosscheck.py`
가 `UnicodeEncodeError`로 그 자리에서 중단된다 — 먼저 빠뜨렸다가 직접 재현
테스트로 발견해 추가함. 환경변수를 설정하고 실행하면 출력이 커밋된
`hh_spacing_analysis_output.txt`·`hh_interval_crosscheck_output.txt`와 바이트
단위로 정확히 일치함을 직접 확인했다.)
(이번 T2-14는 T2-11/T2-12에서 이미 받아둔 song2.json을 재사용 — 동일 song
id=2, MusicDelta_Grunge, 175개 노트. `$QA_USER`/`$QA_PASS`는 QA 계정 정보를
환경변수로 넘기라는 뜻 — 비밀번호를 레포에 평문으로 커밋하지 않기 위함
[CLAUDE.md §5 비밀번호 커밋 금지]. 계정 자체는 사용자에게 이미 안내된
QA 전용 계정이다.)

===== 1차 분석: HH 전체 간격 통계 + 전역 평균 기반 추정 =====
스크립트: qa-evidence/T2-14/hh_spacing_analysis.py
명령: python hh_spacing_analysis.py song2.json (qa-evidence/T2-14/hh_spacing_analysis_output.txt 전문 보존)
결과(발췌):
  SN-HH 정확 일치: 분석 구간(9~13마디) 10/10, 곡 전체 30/46
  HH 연속 간격(곡 전체, 200틱 미만만 — 급격히 큰 간격을 걸러내는 분석 편의상
    휴리스틱 필터, 전부 "마디 경계"라고 증명된 건 아님, n=118): 평균 120.03틱,
    표준편차 4.01, 최소 110, 최대 132 (이상값 110틱)
  마디당 HH 타격 수 분포(표본 내): 7개(10개 마디), 8개(5개 마디), 그 외 불규칙 3개
  전역 평균 기반 추정: (120.03-110)×8 = 80.2틱/마디

===== Codex 모드B 1차 지적 — 전역 평균×명목 타격수는 메커니즘을 직접 증명 안 함 =====
지적: "이 비교는 수치가 비슷한 정도이지, HH 간격이 실제로 그 마디의 SN 드리프트를
  만들어낸다는 걸 직접 보여주지 않는다 — (120.03-110)×8 계산은 전역 평균과 가정된
  타격 수(8)에 기댄 추정일 뿐."

===== 2차 분석: 가정 없는 구간별 실측 =====
스크립트: qa-evidence/T2-14/hh_interval_crosscheck.py
명령: python hh_interval_crosscheck.py song2.json (qa-evidence/T2-14/hh_interval_crosscheck_output.txt 전문 보존)
방법: 전역 평균도, 명목 타격 수(8)도 가정하지 않고, T2-13이 실제로 비교에 쓴
  "SN-HH 동기점"(각 마디의 둘째 SN=그 틱의 HH, T2-13 backbeat_drift_analysis.py와
  동일한 정의) 사이사이에 실제로 몇 번의 HH 타격이 있었는지 하나하나 세어 경과
  틱을 직접 구함.
결과:
  동기점(절대 틱): [8408, 9363, 10318, 11277, 12245]
  9→10마디: 경과 955틱, 실제 HH 타격 8회, 1마디(880틱) 대비 초과 75틱(타격당 9.38틱)
  10→11마디: 경과 955틱, 실제 HH 타격 8회, 초과 75틱(타격당 9.38틱)
  11→12마디: 경과 959틱, 실제 HH 타격 8회, 초과 79틱(타격당 9.88틱)
  12→13마디: 경과 968틱, 실제 HH 타격 8회, 초과 88틱(타격당 11.0틱)
  구간별 초과분 평균: 79.25틱/마디, T2-13 회귀값(78.80틱/마디)과 비율 1.006

===== Codex 모드B 2차 지적 — "독립 교차검증" 표현이 증거의 독립성을 과장함 =====
지적: "이 동기점은 T2-13의 SN 드리프트 회귀에 쓴 바로 그 틱 값이다 — 구간별
  초과분이 T2-13 회귀 기울기와 거의 같다는 건 같은 데이터를 다른 방식으로 봐도
  비슷하게 나온다는 것이지, 서로 독립적인 두 측정이 우연히 일치한 게 아니다."
  또한 재현 명령(curl → song2.json, 현재 디렉터리)과 스크립트가 읽는 하드코딩된
  절대경로가 달라 "명령대로 받아도 스크립트 입력으로 안 쓰인다"고 지적.
반영: (1) `hh_interval_crosscheck.py`를 이 구간에 실제로 몇 번의 HH 타격이
  있었는지(8번, 가정 아니라 실측)와 그로부터 나온 "타격당 초과분"(9.4~11.0틱,
  §1의 전역 평균 초과분 10.03틱과 같은 범위)까지만 서술하도록 수정 — "독립 일치"
  주장 삭제. (2) 두 스크립트 모두 하드코딩된 절대경로 대신 `sys.argv[1]`로 입력
  파일 경로를 받도록 수정, 이 로그에 그 인자를 포함한 정확한 재현 명령 전체를
  기록(위 "분석 데이터 획득" 절).

===== 결론의 범위(과장 방지) =====
"SN이 HH와 정확히 같은 위치에서 관찰되고, HH 자체 간격의 전역 평균 초과분과
국소 구간(9~13마디)의 타격당 초과분이 서로 같은 범위에 있다"는 관찰까지는
가정 없는 실측으로 뒷받침됨. "SN의 드리프트가 HH 때문이다"라는 인과관계까지
수학적으로 증명된 건 아님(둘 다 같은 근본 원인의 결과일 수도 있음) — 다만 실용적
결론("SN만 독립적으로 흔들리는 게 아니다")은 어느 쪽이든 같음. 드리프트의 근본
원인(사람 연주 템포 변동 vs ADTOF 자동 채보 모델의 편향)은 원본 오디오 없이는
여전히 미확정.
