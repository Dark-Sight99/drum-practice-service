# T3-61 결과

## 배경 (의뢰인 요청, 2026-10-29, T3-60과 같은 메시지의 나머지 1건)
"연주화면에서 연습하다가 편집으로 넘어오면 소리가 동기화가 안되는거 같은데
... 다만 여기서 드럼소리는 드럼원곡으로 (연습페이지에서 가상드럼을 켜고있었
더라도) 소리를 맞춰줘. 예를들어 가상드럼소리가 80이었어. 그럼 편집페이지에선
원곡드럼소리가 80으로 되게." — T3-60에서 믹서를 4채널로 통일했지만, 이
부분(드럼 채널 간 음량 이전)은 계정 전체 공유 저장소에 실제로 쓸지, 편집
세션에서만 보여줄지 애매해 `AskUserQuestion`으로 확인 후 진행(T3-60
qa-evidence의 "대화·확인 필요 B" 참고) — **답: 편집 중에만 적용, 저장 안 함**
(연습 화면으로 돌아가면 원래 가상드럼 음량으로 다시 들림).

## 구현 (REQ-05)
`EditorScreen.tsx`에 세션 전용(비영속) 오버레이 추가:
- `drumOverrideActive`/`drumOverrideVolume` — 계정 믹서를 불러온 직후
  (`fetchMixerSetting()` 응답 처리 안) 1회 계산: **원곡 드럼이 꺼져있고(0)
  신스 드럼만 들리고 있었다면**(연습 화면의 "원곡 드럼 켜기/끄기" 프리셋이
  만드는 바로 그 상태) 신스 드럼 음량을 "드럼원곡" 쪽으로 빌려와 켠다. 둘 다
  조절돼 있거나 원곡 드럼이 이미 뭔가로 설정돼 있으면(의도적 조합일 수
  있어) 손대지 않는다.
- `drumOverrideEngaged = drumOverrideActive && audioTracksAvailable` — 실제
  오디오·UI에 적용할 때는 이 값을 쓴다(아래 "자체 재검토" 참고, 이유 있음).
- 저장소(`mixerState`, `saveMixerSetting()`로 계정에 쓰이는 그 객체)는
  **전혀 건드리지 않는다** — 오버레이는 (1) 재생 중 실제 게인 적용(믹서-
  재생 동기화 effect에서 `synthGain.gain.value`·`tracks.setChannelGain
  ('stem_drums', ...)` 계산에만 반영), (2) 두 슬라이더의 **화면 표시값**만
  바꿔 보여준다. "드럼원곡"·"신스 드럼" 슬라이더 중 하나라도 사용자가 직접
  움직이면 `drumOverrideActive`를 꺼서 그 뒤로는 평소처럼 독립적으로
  동작·저장되게 한다(의뢰인이 수동으로 다시 맞추고 싶을 때를 위한 탈출구).

## 자체 재검토 — 개발 중 발견해 직접 고친 문제 (REQ 변경 아님, 구현 중 자가 발견)
처음 구현은 "원곡 드럼이 0이고 신스가 켜져 있으면" 조건만으로 오버레이를
켰는데, 실제로 돌려보기 전에 코드를 다시 읽다가 두 가지 실제 무음 회귀를
발견해 고쳤다:
1. **이 곡에 원곡 드럼 트랙 자체가 없는 경우**(음원 분리가 안 된 곡, 또는
   분리는 됐지만 드럼만 빠진 경우) — 대체할 소리가 없는데 신스만 무음
   처리하면 편집 중 드럼이 완전히 안 들린다. → `canUseAudioTracks &&
   stemKinds.includes('stem_drums')`를 추가로 확인해야만 오버레이 계산
   자체를 켠다.
2. **트랙이 있어도 아직 로딩 중이거나 결국 로딩에 실패한 경우** — (1)의
   조건만 보면 통과하지만 실제로 재생 가능한 원곡 드럼은 아직(또는 영원히)
   없다. → `drumOverrideEngaged`로 `audioTracksAvailable`(실제 로딩 완료
   확인)까지 함께 봐야만 신스를 무음 처리하도록 분리.
또한 이 오버레이 계산이 `stemKinds`/`canUseAudioTracks`를 참조하는데, 원래
믹서 로딩 effect가 그 두 값보다 **먼저** 선언돼 있어 참조 시 TDZ(temporal
dead zone) 런타임 에러가 날 상황이었음 — effect 전체를 그 두 값 선언 바로
다음으로 옮겨 고쳤다(타입체크·린트는 통과했지만 `npx vitest run`을 실제로
돌려 모든 EditorScreen 렌더 테스트가 깨지지 않는 것으로 재확인).

## Codex 모드A 검수(읽기 전용)
- 대상: `task/T3-61-editor-drum-volume-takeover` vs `main`(코드 변경분만).
- **1차 — REQUEST_CHANGES(필수 1건)**: `ensureVoicesSession()`이 새
  `Tone.Gain`을 만들 때 `effectiveGain(mixerStateRef.current.synth_drums)`로
  초기화해, 오버레이가 이미 켜져 있는 상태에서 "처음" 재생을 누르면(아직
  `voicesSessionRef`가 비어 있던 시점) 신스 드럼이 오버레이를 무시하고
  원래 음량 그대로 생성돼 원곡 드럼과 겹쳐 들림 — 믹서-재생 동기화 effect는
  `voicesSessionRef`가 ref라 그 세션이 막 채워진 것만으론 재실행되지 않아
  스스로 안 고쳐짐(사용자가 믹서를 한 번이라도 더 만져야 비로소 바로잡힘).
  **반영**: `synthGain` 생성 시점에 `drumOverrideEngaged ? 0 : effectiveGain(...)`
  로 바로 오버레이를 적용 — "처음 재생"부터 정확.
  확인된 사항(그 외): TDZ 문제 없음(effect 위치 재확인), `drumOverrideEngaged`가
  실제 쓰이는 모든 곳(게인 적용·슬라이더 표시)에서 raw `drumOverrideActive`
  대신 쓰이고 있음, 수동 조작 시 오버레이가 해제되고 다시 안 켜짐(마운트
  1회 효과라 재진입 경로 없음), 회귀 테스트가 고치기 전 코드로는 실제로
  실패했을 것(무음 트랙 게이트 검증에 의미 있음).
- `npx tsc -b`·`npx oxlint`(기존 경고 4건만)·`npx vitest run`(301/301) 재확인.
- **2차(수정분만 재검수) — APPROVE(지적 없음)**. `drumOverrideEngaged`가
  `ensureVoicesSession()` 호출 시점의 렌더 클로저에서 올바른 최신값을
  읽고, 첫 `Tone.Gain`이 오버레이 중엔 0으로 초기화되며, 그 외 신스 게인을
  만들거나 되돌리는 경로가 더 없음을 확인.
