# T3-3 게이트 피드백 1차 — BPM·루프 숫자칸 입력 버그

## 배경
의뢰인이 실기기(아이폰)로 T3-3을 테스트하던 중 "BPM을 숫자로 입력하고 싶다"고 했고, 이어서 A-B 루프 시작 마디를 1→3으로 바꾸려고 "1"을 지우고 "3"을 입력했더니 "13"이 돼버린다고 보고.

## 원인(추측 아님, 코드로 확인)
`clampBpm`/`clampLoopStart`/`clampLoopEnd`가 `Number.isNaN(value)`만 특별 취급하는데, 입력칸을 전부 지우면 `e.target.value===''`이고 `Number('')===0`(NaN이 아님) — 그래서 즉시 `Math.max(1, 0)` 등으로 clamp돼 최솟값으로 되돌아간다. Controlled input이라 이 clamp된 값이 그 순간 바로 화면에 다시 반영되므로, 사용자가 "지우는" 순간이 화면에 전혀 안 보이고(항상 "1"로 즉시 복귀), 바로 이어서 입력한 "3"이 그 "1" 뒤에 이어 붙어 "13"이 된다.

## 수정
BPM·루프 시작·루프 끝 3개 숫자칸 모두 같은 패턴으로: 포커스 중에는 별도의 문자열 draft state로 자유롭게(빈 문자열 포함) 입력을 받고, **포커스를 벗어날 때(`onBlur`)만** 실제 상태로 clamp해 커밋한다. 포커스 중이 아닐 때는 draft를 렌더링 중에 실제 상태값에서 바로 파생시켜(`isEditingX ? draft : String(실제값)`) 슬라이더 등 다른 경로로 값이 바뀌어도 항상 최신값이 보이게 했다 — 처음엔 `useEffect`로 동기화했다가 oxlint의 `react(set-state-in-effect)` 경고(불필요한 추가 렌더 유발)를 받아, effect 없이 렌더링 중 직접 파생하는 방식으로 다시 작성.

순수 입력창 상태 처리 변경 — 오디오 타이밍·API·DB 변경 없음. 위험 작업 아님(T2-15·T3-2-feedback-1과 같은 기준), Codex 모드A만 진행.
