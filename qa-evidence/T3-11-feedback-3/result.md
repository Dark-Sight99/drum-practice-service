# T3-11 게이트 피드백 3차 QA 결과

## 근거(REQ)
- REQ-06 "드럼 연습 화면".
- 의뢰인 피드백(2026-10-25, 실기기 스크린샷 첨부): "폭을 조금 더 줄여도 될거 같아. 그리고 레인도 외각을 선으로 감싸서 레인크기를 보고 싶어. 이건 밝은 대비되는색이 아니어도 될거 같고."

## 변경 내용 (`app/web/src/features/practice/PracticeCanvas.tsx`만 수정)
1. `PRACTICE_LANE_MAX_WIDTH_PX` 520 → 400(추가 축소, 추정치 — `intent/07-open-questions.md` Q-29 갱신).
2. `<canvas>` 스타일에 `border: '1px solid var(--border)'` 추가 — 레인 영역의 경계(크기)가 보이도록. 노트 halo(밝은 `--text`)와 달리 "경계만 보이면 됨"이라는 의뢰인 요청대로 이미 쓰던 차분한 `--border` 토큰(#2E3340) 재사용, 새 색 추가 없음.

## 위험 분류
숫자 상수 변경 + CSS `border` 한 줄 추가, 레이아웃·판정 로직과 무관 — 모드C 생략, 모드A만 진행.

## 브라우저 수동 검증 (localhost:5174, huibigyocha 곡)
- 의뢰인 스크린샷과 비슷한 폭(430px)으로 에뮬레이션 — 캔버스가 400px로 줄고 오른쪽에 여백이 생기며, 그 둘레에 차분한 회색 테두리가 또렷이 보임을 확대 캡처로 확인.
- 더 좁은 폭(283px, 400px 미만)에서는 캔버스가 기존처럼 폭 전체를 채우되 테두리는 그대로 보임(회귀 없음) — 테두리는 폭 제한과 무관하게 항상 표시됨.
- 콘솔 에러 0건.

## 모드A 지적(마스터 판단으로 수정 없이 수용)
- **Low — 테두리가 렌더러 측정 폭을 2px 줄임**: 전역 CSS가 `box-sizing: border-box`라 캔버스의 `border: 1px solid`(상하좌우 각 1px)가 `clientWidth`/`clientHeight`를 2px씩 줄임 — `laneRenderer.ts`가 매 프레임 `clientWidth`로 내부 해상도를 맞추므로 비트맵이 400px가 아니라 398px가 됨. 400px 중 0.5%라 육안으로 구별 불가한 수준— 테두리를 감싸는 별도 `<div>`로 옮기는 수정은 이 정도 오차 대비 과한 작업이라 판단, 수정 안 함.

## 결론
숫자 조정 + CSS 테두리 추가의 최소 변경으로 의뢰인이 지적한 두 가지(폭 추가 축소, 레인 경계 가시성) 모두 해결. 400px도 추정치라 추가 피드백으로 조정 가능(Q-29).
