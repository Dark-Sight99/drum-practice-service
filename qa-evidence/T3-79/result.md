# T3-79 QA 증거

## 배경
의뢰인이 "16격자인데 1/4씩 움직이는거 같다"고 지적. 확인해보니 수치 자체는 맞았음(16분음표 한 칸=1박의 1/4이라 "+1/4"로 표시된 것, 격자 선택과 이동 간격이 둘 다 16분음표 기준으로 일치) — 다만 의뢰인의 실제 요청은 "격자 설정(보기용 확대 배율)과 무관하게 화살표 이동은 항상 1/16 단위로 고정해달라"는 것이었음. 지금까지는 "격자" 드롭다운이 화면 표시 배율과 화살표 이동 간격을 동시에 결정하고 있었음.

## 구현
`app/web/src/features/editor/EditorScreen.tsx`:
- 기존 `unitTicks`(격자 드롭다운에 따라 바뀜, 그리드선 간격·픽셀 변환·클릭 스냅 허용오차에 계속 사용)는 그대로 두고, **`keyboardNudgeTicks = ticksPerGridUnit('16n', ppq)`**(항상 16분음표, 격자 설정과 무관)를 새로 추가.
- 화살표 키 이동(`handleGridKeyDown`의 ArrowLeft/ArrowRight)과 `moveSelected`의 반올림-오차-누적 방지 로직(T3-77) 전부 `unitTicks` 대신 `keyboardNudgeTicks` 사용.
- T3-77에서 "격자 설정이 바뀌면 이동 기준점을 다시 잡으려고" 추가했던 anchor의 `gridUnit` 필드는, 이동 간격이 더는 격자 설정과 무관해졌으므로 제거.

## 테스트
- `npx tsc -b`: 에러 없음
- `npx oxlint`: 기존부터 있던 무관한 경고 4건만
- `npx vitest run`: **335 passed**(25 test files) — 기존 3건이 "이동 간격이 선택된 격자를 따라간다"고 가정했던 걸 "항상 ppq/4"로 갱신(그 중 반올림-오차 회귀 테스트는 ppq=100→90으로 바꿔 non-integer 스텝 시나리오를 다시 확보).

## 실브라우저 확인
song 9 편집기에서 **격자를 일부러 "4분"(가장 거친 설정)으로 둔 채** HH 노트(틱 3511) 선택 후 →키 한 번 → **정확히 3566(+55틱=1/16박)으로 이동** — 격자 설정과 무관하게 항상 16분음표 단위로 움직임을 확인.
