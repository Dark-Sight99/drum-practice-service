> 한 줄 요약: 기존 노트를 클릭해 선택할 때 포커스가 그 노트로 안 옮겨가던 버그(다른 컨트롤을 만진 뒤 노트를 다시 클릭하면 화살표 키가 안 먹힘) 수정. 실브라우저로 재현·확인, 회귀 테스트가 수정 전엔 실패함을 직접 검증, Codex 모드A APPROVE.

# T3-78 QA 증거

## 배경
의뢰인이 "노트 생성하고 다른거 만지다(실행취소, 격자 바꾸기 등) 그 노트 다시 클릭 후 키보드 누르면 안 움직인다"고 보고.

## 재현(실브라우저)
1. 편집기에서 빈 칸 클릭해 MT 노트 생성(틱 545) — 자동 선택됨.
2. "격자" 드롭다운을 16분으로 변경(포커스가 드롭다운으로 이동).
3. 방금 만든 노트를 다시 클릭(재선택).
4. → 키를 눌러도 **틱이 545에서 전혀 안 바뀜**(재현 확인).

`document.activeElement`를 직접 찍어보니, 3번(노트 재클릭) 이후에도 여전히 `<select>`(격자 드롭다운)가 포커스를 갖고 있었음 — 노트 버튼이나 그리드 컨테이너로 포커스가 전혀 안 넘어감.

## 원인
`handleNoteMouseDown`(기존 노트 클릭 시 onMouseDown)이 "드래그 중 텍스트 선택 방지"를 위해 `e.preventDefault()`를 호출하는데, 이게 **브라우저의 "클릭 시 이 버튼에 포커스" 기본 동작도 같이 막아버림**. 그래서 클릭 직전에 포커스가 다른 곳(격자 드롭다운, 실행취소 버튼 등)에 있었다면, 노트를 클릭해 선택해도 포커스는 그대로 그 다른 곳에 남고, 화살표 키 이벤트(그리드 컨테이너의 `onKeyDown`)가 전혀 안 와서 "눌러도 안 움직이는" 것처럼 보임.

**새 노트를 빈 칸 클릭으로 만들 때는 이 문제가 없었음**(`handleRowClick`은 mousedown 핸들러 자체가 없어 preventDefault를 안 함 — 포커스 없는 자식을 클릭하면 브라우저가 알아서 가장 가까운 포커스 가능한 조상인 그리드 컨테이너(`tabIndex=0`)로 포커스를 넘겨줌). 그래서 "만들자마자 바로 화살표로 옮기기"는 항상 잘 됐고, "다른 데 갔다가 기존 노트를 다시 클릭"하는 경로에서만 재현됐음.

## 수정
`handleNoteMouseDown`의 `e.preventDefault()` 바로 다음 줄에 `e.currentTarget.focus()`를 추가해, preventDefault가 없앤 포커스를 명시적으로 되돌림.

## 테스트
- `npx tsc -b`: 에러 없음
- `npx oxlint`: 기존부터 있던 무관한 경고 4건만
- `npx vitest run`: **335 passed**(25 test files, 신규 1건 포함)
- **회귀 테스트가 진짜인지 직접 검증**: `.focus()` 줄을 일시적으로 지우고 신규 테스트만 재실행 → **실패**(activeElement가 여전히 select) 확인. 다시 복구 후 전체 테스트 통과 재확인.

## 실브라우저 확인
재현 시나리오(노트 생성 → 격자 변경 → 노트 재클릭 → →키)를 수정 후 다시 실행 — `document.activeElement`가 이제 그 노트 버튼으로 확인되고, →키로 틱이 545→600(+55, 정확히 1/16박)으로 이동함을 확인.

## Codex 모드A
APPROVE(지적 없음) — `e.currentTarget` 타입, 드래그 기능과의 상호작용, 새 노트 생성 경로 영향 없음, 테스트의 타당성까지 전부 확인 완료.

## 결론
의뢰인이 직접 겪은 버그를 정확히 재현해 근본 원인(포커스 억제)을 찾아 수정했고, 수정 전엔 실패하는 걸 직접 확인한 회귀 테스트까지 추가했다.
