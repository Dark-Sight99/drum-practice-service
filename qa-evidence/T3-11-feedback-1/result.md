# T3-11 게이트 피드백 1차 QA 결과

## 근거(REQ)
- REQ-06 "드럼 연습 화면".
- 의뢰인 피드백(2026-10-25): "배경도 검은색인데 외각선도 검은색이라 잘 구분이 안되. 각자 색이 지금 있잖아. 반대로 흰색 외각선이나 각자 노트마다 색이 있는데 그 색 계열의 잘 보이는 외각선을 해주는건 어때?" → 의견 교환 후 흰색(기존 `--text`) 계열로 결정(피스별 색 테두리는 킥(#D9DDE6)이 이미 흰색에 가까워 본체-테두리 경계가 흐려질 수 있다는 점을 설명, 흰색 단일 계열로 진행).

## 변경 내용 (`app/web/src/render/laneRenderer.ts`만 수정)
- 노트 halo 색을 `options.laneHeaderBackgroundColor`(--bg, 어두운 배경색 — T3-11에서 처음 실수로 쓴 값)에서 `options.stickingTextColor`(--text, 밝은 색 — 원래 R/L 글자용으로 이미 렌더러에 전달되던 값)로 교체. 새 CSS 토큰·새 옵션 추가 없이 기존에 이미 전달되던 값을 재사용.

## 위험 분류
한 줄짜리 색상 인자 교체(이미 존재하는 밝은 색 옵션을 재사용)라 모드C 생략, 모드A만 진행.

## 브라우저 수동 검증 (localhost:5174, huibigyocha 곡)
재생 시작 후 확대 캡처(zoom)로 스네어·킥 연타 사이에 흰색 테두리가 또렷이 보임을 확인(이전엔 어두운 테두리가 어두운 배경에 묻혀 안 보였음). 콘솔 에러 0건.

## 결론
기존에 이미 렌더러에 전달되던 밝은 색(`--text`)을 재사용하는 최소 변경으로 의뢰인이 지적한 "테두리가 배경에 묻힘" 문제 해결. 피스별 색 테두리(대안 2)는 일부 피스(킥)의 기존 색이 이미 흰색에 가까워 역효과가 날 수 있다고 판단해 채택하지 않음 — 추후 피드백으로 재검토 가능.
