# T3-58 결과

## 배경 (의뢰인 요청, 2026-10-29)
"편집 페이지에 대한 기능 수정이 필요할 거 같아. 편집시에도 음악을 들으면서
할 수 있을까? ... 연주 페이지에서 편집 버튼을 누르면 편집하는 페이지의
해당 부분으로 바로 이동해서 편집 바로 할 수 있게 할 수 있을까? 편집페이지
에서도 믹서 동일하게 사용. ... 편집 페이지에 격자는 무슨뜻이야? 그리고
bpm이나 박자표를 수정하면 실제 곡의 bpm이나 박자표의 기본값이 바뀌는거지?
또한 자동추천 재적용 버튼은 삭제해줘. 필인시작손도 삭제. 저장버튼은 실제
변경하지 않았을 땐 비활성화 했다가... 변경값이 있을때만 저장버튼 활성화
되게 해줘. 실행취소 다시실행도 아이콘으로 바꿀수 있으면 추천해줘."

## 질문에 대한 답 (코드 확인)
- **"격자"란?** 편집기 그리드의 스냅 단위(4분/8분/16분/8분셋잇단) —
  노트를 찍거나 화살표키로 옮길 때 어느 간격(음표 길이)으로 달라붙을지
  정한다(`grid.ts`, 피아노롤 에디터의 흔한 "snap to grid"와 같은 개념).
- **BPM/박자표 수정 → 실제 곡 기본값이 바뀌는지?** 저장을 누르면 네 —
  `GET /songs/{id}/drumscore`가 수정본(`DRUMSCORE_EDITED`)을 원본보다
  우선해서 돌려주므로(`songs.py`), 연습 화면 등에서 다음에 불러올 땐
  바뀐 BPM/박자표가 적용된다. **다만 발견한 문제**: 라이브러리 목록에
  뜨는 BPM(`Song.original_bpm` 컬럼)은 편집 저장과 전혀 연동돼 있지
  않아서, 편집기에서 BPM을 바꿔 저장해도 라이브러리 목록엔 예전 BPM이
  계속 보입니다. 이건 "원본 BPM은 늘 원본 그대로 남겨두는 게 의도"일
  수도 있어 이번 작업에서 임의로 고치지 않았습니다 — 다음 턴에
  의뢰인께 어느 쪽을 원하시는지 확인 후 처리 예정(intent/07-open-questions.md
  후보로 등록할 만한 사안).

## 구현

### 1) 편집 중 재생 (`EditorScreen.tsx`)
신스 드럼 + 메트로놈만 재생(원곡 음원 스템은 이번 범위에서 뺌 — 아래
"범위를 줄인 이유" 참고). 재생/일시정지 버튼(▶/⏸ 아이콘) + 분:초 표시 +
그리드 위 재생 위치선(세로 막대). "재생"을 누르면 그 시점의 `history.present`
(편집 중인 최신 노트·BPM·박자표)를 즉시 반영해 재생 — 편집하다 다시 재생을
누르면 바뀐 내용이 바로 들림.

**범위를 줄인 이유(원곡 음원 스템 미포함)**: practice 화면의 실제 분리
음원(보컬/베이스 등) 재생은 `prime()`→`playFrom()`→`resync()`로 이어지는
훨씬 복잡한 파이프라인이고, 이 프로젝트가 과거에 그 경로에서 반복적으로
겪은 동기화 버그들(T3-16-feedback-6/7, T3-47 루프 경계 등, 전부 몇 라운드의
Codex 검수를 거쳐서야 해결됨)이 있습니다. 편집 화면이 요구하는 "재생
시작하자마자 임의 위치로 점프"는 그 경로와 섞으면 똑같은 부류의 버그를
새로 만들 위험이 커서, 노트 트리거(각 노트를 개별 `transport.schedule()`로
예약하는 단순한 경로 — 지나간 노트는 Tone.js 표준 동작으로 그냥 스킵됨,
"점프 후 재생"이 자연히 안전함)만 쓰는 신스 재생으로 범위를 좁혔습니다.
편집 중인 패턴을 듣는다는 핵심 목적은 이걸로 달성되고, 원곡 전체 믹스가
꼭 필요하면 별도 작업으로 확장 가능.

### 2) 믹서 (`EditorScreen.tsx`)
"믹서 동일하게"를 "같은 계정 전체 설정(`/auth/me/mixer-setting`, practice
화면과 완전히 같은 저장소)을 그대로 쓴다"로 해석 — 신스 드럼·메트로놈
슬라이더를 두고, 바꾸면 그 설정이 계정 전체(practice 화면 포함)에 그대로
반영됩니다. practice 화면의 채널별 편집-추적·저장 요청 직렬화 같은 정교한
경합 방지(PracticeCanvas.tsx, T3-28/T3-29 몇 라운드에 걸쳐 다듬어진 로직)는
이 화면 세션이 짧고 단순해 생략 — 단순 디바운스(500ms) 저장으로 충분하다고
판단.

### 3) 연주 → 편집 위치 이어가기 (`PracticeCanvas.tsx`, `App.tsx`)
PracticeCanvas에 "편집하기" 버튼(믹서 패널 맨 위) 추가. 클릭 시점의
재생/일시정지 위치를 `clock.getPositionSeconds()`로 읽어 틱으로 환산해
`onEditSong(song, score, positionTicks)`로 App.tsx에 넘기고, App.tsx가
`editorInitialPositionTicks`에 담아 `EditorScreen`에 전달. EditorScreen은
마운트 시 그 위치로 그리드를 스크롤만 하고(재생 위치선도 거기서 시작)
**자동으로 재생을 시작하지 않습니다**(의뢰인 명시 — "연주페이지에서
재생되는동안 편집페이지에서도 동일하게 재생되고 있으면 안됨"). 연주 화면이
언마운트되는 순간 기존 정리 로직(`useEffect(() => stopPlayback, [])`)이
알아서 재생을 멈추므로 별도 처리 불필요. 틱 환산은 scorePlayer.ts가 노트를
`playbackBpm`(연습 속도, 원곡 BPM이 아님) 기준으로 예약한다는 사실과
정확히 맞춰 역산.

### 4) 저장 버튼 dirty-state (`EditorScreen.tsx`)
실행취소/다시실행(`editHistory.ts`)이 과거 상태 객체를 새로 안 만들고
그대로 재사용한다는 점을 이용 — "저장된 시점의 state 객체 참조"와 지금
참조를 비교하기만 하면 값 비교 없이 정확히 판정됨(실행취소로 저장 시점까지
되돌아오면 자동으로 다시 비활성화됨 — 테스트로 확인). 버튼은 기존 전역
`button:disabled` 스타일(흐려짐)로 시각적으로도 비활성 표시됨 — 추가 CSS
불필요.

### 5) 자동추천 재적용 · 필인 시작손 삭제
`applyAutoRecommend`/`startHand` 전부 제거, `recommendSticking` import도
삭제(다른 곳에서 쓰이지 않음을 확인). **알려드릴 점**: 코드 전수 확인
결과 이 버튼이 노트 전체에 손(R/L) 추천을 일괄 적용하는 **유일한
경로**였습니다(서버 쪽엔 이런 자동 추천 로직이 없음) — 삭제하면 이제
손 지정은 노트 하나씩 선택해 R/L/RF/LF 버튼으로 하거나(기존 기능, 유지),
여러 개 선택 후 "RLRL/LRLR 교대"(기존 기능, 유지)로만 가능합니다.

### 6) 실행취소/다시실행 아이콘화
lucide-react `Undo2`/`Redo2`로 교체(이미 설치된 버전에 존재 확인,
`node_modules`에서 `undo-2.js`/`redo-2.js` 확인). `aria-label`·`title`은
기존 텍스트("실행취소"/"다시실행") 그대로 유지해 스크린리더·툴팁에서는
안 바뀜.
