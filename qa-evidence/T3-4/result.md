# T3-4 믹서(볼륨/M/S/프리셋) 결과

## 설계
`work/T3-4/plan.md` — Codex 모드C 3라운드(1·2라운드 REQUEST_CHANGES, 3라운드도 REQUEST_CHANGES였으나 `intent/06-pipeline.md` "재검수는 최대 3회" 규칙에 따라 마스터가 직접 판단해 잔존 위험을 수용·문서화). 라운드별 반영 내용:
- 1라운드: 솔로/음소거 규칙 명문화(솔로가 음소거를 이김, 다중 솔로 허용), 디바운스 저장 유실 방지(언마운트 flush), 공용 Gain 노드 생명주기 명시, 재생 중 게인 적용의 경쟁 방지(`playbackRef.current` 존재 여부로 게이트), 동시 최초 PUT 경쟁(T2-6 "낙관적 upsert" 재사용).
- 2라운드: 같은 탭 안에서 저장 요청 2개가 동시에 떠 있다가 네트워크 지연으로 순서가 역전될 수 있다는 지적 → 클라이언트 측 요청 직렬화(진행 중이면 플래그만 세우고 안 보냄, 끝나면 최신 상태로 한 번만 더 보냄).
- 3라운드(최종): 모호한 네트워크 실패(reject됐지만 서버는 실제로 받아 나중에 처리하는 경우) 시의 좁은 순서 역전 잔존 위험 — DB 버전 필드 없이는 완전히 못 막음. 비용(스키마 변경, 위험도 상승) 대비 피해(믹서 설정 하나가 살짝 되돌아갈 뿐, 파괴적이지 않고 재조작으로 바로 복구) 작음을 근거로 마스터가 수용.

## 구현
- **백엔드**: `GET`/`PUT /songs/{id}/practice-setting`(`app/server/api/songs.py`) — 기존 `PracticeSetting` 테이블 재사용(마이그레이션 없음), 채널 키 6개 고정 검증(`api/schemas.py`의 `PracticeSettingIn`/`Out`), `volumes_json`만 갱신(`practice_bpm`/루프 컬럼 안 건드림), T2-6과 동일한 낙관적 upsert로 동시 최초 생성 경쟁 방어.
- **프런트**: `app/web/src/audio/mixer.ts`(신규, 순수 함수 — `effectiveGain`의 솔로/음소거 규칙, `toggleDrumlessPreset`, `linearGainToDb`), `drumVoices.ts`(`createDrumVoices(destination?)`로 공용 `Tone.Gain` 경유 가능, 하위 호환 유지), `trackPlayer.ts`(`setChannelGain(kind, gain)` 추가), `metronome.ts`는 기존 그대로 재사용하되 **처음으로 `PracticeCanvas.tsx`에 연결**(T2-4가 미뤄뒀던 부분). `PracticeCanvas.tsx`에 마운트 시 불러오기(GET)+방어적 기본값 채우기, 재생 중 즉시 반영(§QA계획대로 `playbackRef.current` 게이트), 저장 요청 직렬화(savingRef/pendingSaveRef)+400ms 디바운스+언마운트 flush, 6행 믹서 UI + 프리셋 버튼.

## 자동 테스트
- 백엔드: `pytest` 160개 전부 통과(기존 150 + 신규 10 — 소유권 404, 채널 키/범위 검증 422, `practice_bpm`/루프 컬럼 불변, **동시 최초 PUT 경쟁 재현 회귀 테스트**(T2-6과 같은 패턴)), `ruff check` 0건.
- 프런트: `vitest` 171개 전부 통과(기존 154 + 신규 17 — `mixer.ts` 14개: 솔로 없음/1개/여러 개/솔로가 자기 뮤트를 이김/프리셋이 stem_drums만 건드림/dB 변환, `trackPlayer.ts`의 `setChannelGain` 3개: 올바른 트랙만 설정·범위 클램프·알 수 없는 kind 무시), `oxlint`·`tsc --noEmit` 0건.

## 실제 브라우저(Chromium) 확인
backnumber 곡(song id=10)으로:
1. 연습 화면 진입 → `GET /songs/10/practice-setting` 확인(React StrictMode로 2번 호출되는 건 dev 모드의 의도된 동작, `cancelled` 플래그로 안전하게 처리됨을 확인).
2. "드럼 빼고 듣기" 클릭 → 콘솔로 체크박스 상태 직접 읽어 **stem_drums의 음소거만 켜지고 나머지 5채널은 전부 그대로**임을 확인.
3. `PUT` 발생(네트워크 패널엔 `net::ERR_ABORTED`로 표시됐지만, 서버에 직접 `curl`로 재확인한 결과 **실제로는 204로 정상 저장됨** — T3-3의 스템 Range 요청에서도 봤던 같은 종류의 네트워크 패널 표시 아티팩트로 판단, 데이터 자체는 정확).
4. 페이지를 완전히 새로고침 → 저장된 음소거 상태가 그대로 복원됨을 확인(곡별 마지막 설정 기억, 수용 기준 충족).
5. 프리셋 다시 눌러 원복 → 재생 시작 → **콘솔 에러 없음**(메트로놈이 이번에 처음 실제 재생 흐름에 연결됐는데 문제 없이 동작).
6. 재생 중에 드럼(원곡) 볼륨 슬라이더를 40%로 바꿈 → 화면에 즉시 "40%"로 반영, 콘솔 에러 없음(재생 중 즉시 반영, 수용 기준 충족).
7. 정지 → 재생 → 정지(재생 반복) → 콘솔 에러 없음(공용 Gain·메트로놈의 재생 1회당 생성/정리 생명주기가 깨지지 않음을 확인).
