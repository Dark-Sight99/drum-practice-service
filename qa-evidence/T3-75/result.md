# T3-75 QA 증거

## 배경
의뢰인이 편집 화면·연습 화면을 비교하며, 연습 화면은 "지금"이 항상 화면의 고정된 자리에 있는데 편집 화면은 재생 중에도 화면이 그대로라 재생 위치선만 화면을 가로질러 지나간다고 지적 — 편집 화면도 재생 중엔 연습 화면처럼 커서를 따라가도록 요청.

## 구현
`app/web/src/features/editor/EditorScreen.tsx`:
- 기존에 "연습 화면→편집 화면 진입 시 1회만" 스크롤하던 로직(`initialPositionTicks` effect)에서 쓰던 매직넘버 80을 `PLAYHEAD_SCROLL_LEAD_PX` 상수로 추출(동작 변화 없음, 리팩터).
- 재생 중에만 도는 기존 `startRaf()`의 매 프레임 루프(`loop(ts)`) 안에, 재생 위치선(`playheadRef`) 갱신에 쓰던 `playheadPx` 값을 재사용해 `gridScrollRef.current.scrollLeft = Math.max(0, playheadPx - ROW_LABEL_WIDTH - PLAYHEAD_SCROLL_LEAD_PX)`를 매 프레임 적용 — 재생 위치가 항상 화면의 같은 자리(레이블 바로 다음 + 80px)에 있도록 유지. state를 안 거치고 ref로 직접 쓰므로 리렌더 없음. 재생 중에만 도는 루프 안이라 일시정지·정지·편집 중에는 전혀 동작하지 않음(기존 "편집 중엔 스크롤 안 건드림" 원칙 그대로 유지).

## 테스트

- `npx oxlint`: 기존부터 있던 무관한 경고 4건만

## 실브라우저 확인
song 9 편집기에서 재생 → 0:09, 0:22 두 시점 모두 재생 위치선이 화면의 같은 x 좌표에 고정된 채 그리드가 계속 스크롤됨을 확인(지속 추적, 1회성 점프가 아님). 일시정지 후에는 그 자리에서 스크롤이 멈추고(연습 화면과 동일하게) 되돌아가지 않음을 확인.

## Codex 모드A
**APPROVE**(비차단 UX 메모 1건):
- RAF 콜백 취소·언마운트 경쟁 조건, `gridScrollRef.current` null 체크, 드래그 틱 계산과의 상호작용, 기존 테스트(리터럴 80 단정 없음) — 전부 문제 없음 확인.
- **알려진 트레이드오프(차단 아님)**: 재생 중 매 프레임 `scrollLeft`를 강제로 되돌리므로, 재생 중 사용자가 그리드를 수동으로 옆으로 스크롤해 다른 구간을 보는 건 사실상 불가능해짐(다음 프레임에 바로 원위치) — 이건 의뢰인이 명시적으로 요청한 "항상 따라가기"(연습 화면과 동일) 동작의 당연한 결과.
- **추가로 발견한, 이번 작업 범위 밖의 기존 간극(참고용 기록)**: 편집 화면은 재생 중에도 노트 클릭 추가(`handleRowClick`)·드래그 이동(`handleNoteMouseDown`)이 막혀있지 않음(BPM·박자표 입력 등 다른 컨트롤만 `disabled={isPlaying}`로 잠겨있고, 그리드 자체는 아님) — 재생 중 자동 스크롤까지 더해지면 드래그 중 그리드가 마우스 아래에서 계속 움직여 체감상 혼란스러울 수 있음(계산 자체는 틀리지 않음, 시각적 혼란 가능성). 이건 이번 요청(자동 스크롤)과 무관하게 전부터 있던 간극이라 이번 작업 범위에 넣지 않았음 — 필요하면 "재생 중엔 편집 잠금" 같은 별도 작업으로 제안.

## 결론
요청대로 편집 화면도 재생 중 커서를 계속 따라가도록 구현 완료, main 병합 전 전부 확인.
