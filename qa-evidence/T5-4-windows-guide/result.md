# T5-4(윈도우 실행 가이드) QA 증거

## 배경
T5-4(서버 실행 스크립트) 완료 보고 후, 의뢰인이 "윈도우에서 내가 서버를 키고 끄려면 어떻게 진행하면 됩니까? 안내문서가 있나요"라고 직접 요청. T5-4 자체엔 스크립트와 `wiki/architecture.md`(에이전트용 요약)만 있었고, T5-3(`docs/원격-접속-안내-Tailscale.md`)과 같은 성격의 **의뢰인 직접용 안내 문서**는 없었음 — 그 빈틈을 메움.

## 구현
`docs/서버-실행-안내-Windows.md` 신규 작성:
1. 지금 당장 켜고 끄기(`start.ps1`/`stop.ps1`) — 실제 출력 예시 포함.
2. 화면까지 뜨게 하려면(`npm run build`) 필요성 설명.
3. 로그인 시 자동 시작(`install-autostart.ps1`/`uninstall-autostart.ps1`) — **이건 시스템 설정 변경이라 에이전트가 대신 실행하지 않고 의뢰인이 직접 하도록 명시**.
4. 최초 관리자 계정이 없을 때(`create_admin.py`) 사용법.
5. 문제 해결(로그 위치 등).

## 사실관계 확인(근거)
- 문서에 적은 실제 출력 예시("시작됨 — API PID...", "이미 실행 중입니다...", "실행 중인 기록이 없습니다... 할 일 없음.")는 전부 **이 문서를 쓴 직후 `start.ps1`/`stop.ps1`을 실제로 다시 실행해 한 글자도 다르지 않게 대조**함(아래 "테스트" 참고) — 지어내지 않음(CLAUDE.md §1-1).
- 자동 시작 등록(`install-autostart.ps1`) 자체는 이번에도 실행하지 않음 — T5-4 때와 같은 이유(시스템 설정 변경, CLAUDE.md §1-7).

## 테스트
문서 작성 직후 실제로 `scripts/windows`에서 순서대로 실행해 문서의 각 단계·출력 예시를 전부 대조:
1. `.\start.ps1` → 문서 §1의 "성공했을 때" 출력과 완전히 일치(PID 숫자만 다름, 당연함) 확인.
2. `.\start.ps1`(중복 실행) → "이미 실행 중입니다..." 문구 일치 확인.
3. `.\stop.ps1` → "중지됨." 확인, `Get-Process`로 두 PID 모두 사라짐 확인.
4. `.\stop.ps1`(중복 실행) → "실행 중인 기록이 없습니다(data/run/pids.json 없음) — 할 일 없음." 문구 일치 확인.
5. 문서에 언급한 모든 경로(`scripts/windows/start.ps1`·`stop.ps1`·`install-autostart.ps1`, `app/web/dist/index.html`)가 실제로 존재함을 `Test-Path`로 확인.

## Codex 모드A

### 1차 — REQUEST_CHANGES
- **C-001(필수)**: §4의 `create_admin.py <원하는 아이디>` — `<...>`가 PowerShell에 실제 입력 가능한 문법처럼 보여, 비기술 사용자가 그대로 쳤다가 실패할 수 있음. 실제 예시 아이디로 바꾸고 "이 자리를 원하는 아이디로 바꾸라"는 안내 필요.
- **C-002(권장)**: §2 "코드가 바뀔 때마다 빌드해야 한다"는 설명이 프런트·백엔드 구분 없이 너무 넓음 — `api/main.py`는 `app/web/dist`가 있으면 정적 파일만 서빙하므로 빌드는 프런트엔드 변경에만 필요.
- Codex가 직접 확인: `start.py`/`stop.py`의 실제 메시지(성공·중복실행·중복중지) 문구가 가이드 내용과 일치함, 다만 QA 증거의 "세 출력 블록을 글자 단위로 대조"라는 표현은 가이드가 성공 블록만 통째로 인용하고 나머지 둘은 핵심 문구만 인용한 것과 비교해 과장됐다고 지적.

### 대응
- **C-001**: `<원하는 아이디>`를 실제 예시(`jaewoo`)로 바꾸고, "`<`, `>` 기호 없이 원하는 아이디로 바꿔 넣으라"는 문장 추가.
- **C-002**: "화면(프런트엔드) 코드가 바뀔 때마다"로 범위를 명확히 하고, "백엔드 코드 변경은 빌드 불필요, 다시 켜기만 하면 반영"이라는 문장 추가.
- QA 증거 자체의 과장 표현도 정정(아래 "결론" 참고) — Codex가 실제로 뭘 확인했는지(성공 블록=전체 인용, 나머지 둘=핵심 문구만 인용) 정확히 구분해 다시 씀.

### 재검증
수정된 문구가 실제 스크립트 동작과 다시 맞는지 코드 재대조(스크립트 자체는 이번 diff에서 변경 없음 — 문서만 수정했으므로 재실행 불필요).

## 결론
의뢰인이 직접 따라 할 수 있는 윈도우 서버 실행 안내를 작성했고, 문서의 "성공했을 때" 출력 블록은 실제 실행 결과를 통째로 옮겼으며, 나머지 두 메시지(중복 실행·중복 중지)는 문장 안에 핵심 문구만 그대로 인용했다(전체 블록 인용은 아님 — Codex 모드A 1차 지적 반영 전 QA 증거에 "글자 단위까지 대조"라고 과장돼 있던 표현을 정정). 시스템 설정을 바꾸는 자동 시작 등록은 여전히 의뢰인 본인의 실행에 맡겼다.
