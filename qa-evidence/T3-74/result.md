# T3-74 QA 증거

## 배경
T3-73(모양 통일) 이후에도 의뢰인이 편집 화면·연습 화면을 나란히 비교하며 "노트에서 1박 선까지의 거리가 다르다"고 지적 — 직접 두 화면에 빨간 선으로 표시해 비교한 결과, 편집 화면 쪽이 유의미하게 더 길다는 걸 발견(약 12px vs 약 4px).

## 원인
두 화면이 "정확한 박자 위치"를 노트 도형의 **서로 다른 지점**에 맞춰 그리고 있었음:
- 연습 화면(`laneRenderer.ts`): 도형의 **판정 쪽(하단) 모서리**가 정확한 위치(모드A 기존 지적 반영분, `shapeBottomExtent`로 도형마다 보정)
- 편집 화면(기존): 도형의 **정중앙**이 정확한 위치

편집 화면은 왼쪽=이른 시간이므로, 연습 화면의 "판정 쪽(이른 시간 쪽) 모서리" 기준과 맞추려면 왼쪽 모서리를 정확한 위치에 맞춰야 함. 기존 중앙 정렬은 노트 폭의 절반(8px)만큼 항상 추가로 벌어져 보이는 원인이었음 — 실제 타이밍 데이터 차이가 아니라 **그리는 기준점 차이**였음(검증: 노트 폭 절반을 빼고 다시 계산하면 두 화면이 거의 같은 값, ~4px, 나옴).

## 구현
`app/web/src/features/editor/EditorScreen.tsx` — `left: tickToPx(displayTick) - NOTE_SIZE/2` → `left: tickToPx(displayTick)`. 폭·높이(16px)·행 안에서의 수직 중앙 정렬은 변경 없음. 틱 0 노트가 음수 위치로 라벨 영역을 침범하던 기존 문제(주석에 명시돼 있던)도 이 변경으로 같이 해소됨(`tickToPx(0)`가 항상 `ROW_LABEL_WIDTH` 이상이라).

## 테스트
- `npx tsc -b`: 에러 없음
- `npx oxlint`: 기존부터 있던 무관한 경고 4건만
- `npx vitest run`: **332 passed**(25 test files) — 중앙 정렬을 전제로 한 픽셀 단정 테스트 없음(Codex 모드A도 같은 결론)

## 실브라우저 확인
song 9 편집기에서 "16분" 격자로 확대해 확인 — 노트 왼쪽 모서리가 격자선에 거의 붙어(몇 px의 자연스러운 간격만 남고) 보임, 연습 화면과 동일한 인상.

## Codex 모드A
APPROVE(지적 없음) — 틱 0 처리, zIndex 라벨 레이어링, 클릭/드래그와의 일관성, 기존 테스트의 암묵적 중앙정렬 가정 여부 전부 확인 완료.

## 결론
편집기와 연습 화면 모두 "노트가 가리키는 정확한 위치"를 그리는 기준(이른 시간 쪽 모서리)을 통일. 남은 몇 px 차이는 실제 검출된 타이밍 자체가 정박보다 살짝 이르기 때문(T3-72/Q-43)이며, 두 화면이 이제 그 차이를 동일한 방식으로 보여준다.
