판정: REQUEST_CHANGES
- **C-001**(필수): `process_next_job`이 SELECT와 PROCESSING 전환(commit)을 분리해서 하므로, 워커 프로세스 2개를 동시에 띄우면 둘 다 같은 QUEUED 작업을 선택할 수 있음 — **재현 확인**(파일 기반 SQLite + 별도 커넥션 2개 + 인위적 지연으로 실제 재현, 두 스레드 모두 같은 Job id를 가져감). `_claim_next_job()`을 추가해 `UPDATE ... WHERE id=? AND status='queued'` 단일 문장으로 원자적 선점하도록 수정.
- **C-002**(필수로 지적, 판단 대기): 재시작 복구(`recover_orphaned_jobs`)가 워커 소유자를 구분하지 않아, 워커 B가 시작하면서 워커 A가 정상 처리 중인 작업까지 FAILED로 표시할 수 있음 — 코드 검토로 재현됨(논리상 명백). 제대로 고치려면 Job에 워커 식별자 컬럼을 추가하는 **스키마 변경**이 필요해 파이프라인 자동수정 3조건을 벗어남 → 수정 안 함, `intent/07-open-questions.md` Q-17로 등록(현재는 "워커 프로세스 1개만 운영"이 설계 전제라 실질 위험 낮다고 판단 — 추천일 뿐 결정 아님).
