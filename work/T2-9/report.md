# T2-9 보고 — Phase 2 게이트 2차 피드백

## 위험 작업 여부
이 수정은 노트의 시각(초) 계산을 전혀 안 바꾸고, 이미 올바르게 계산된 시각을 화면의 어느 Y픽셀에 그릴지만 상수(`noteSize/2`)만큼 조정한다 — `intent/06-pipeline.md` §1-1의 "오디오 타이밍·동기"(시각 계산 자체를 바꾸는 작업)에 해당하지 않는다고 판단해 Codex 모드C 생략. T2-7의 표시 전용 변경과 같은 패턴.

## 구현 근거 (실행 결과로 확인)
- **판정 순간 정밀화**: 도형이 `noteSize`(16~28px) 높이를 가지므로 중심 기준 정렬은 하단 모서리가 중심보다 먼저 판정선에 닿고 상단 모서리는 나중에 지나가는 시각 차(현재 낙하속도에서 수십 ms 수준)를 만들었다 — 사용자가 "하단이 닿을 때"를 명시적으로 요청해 리듬게임 관례(리딩 엣지 기준)에 맞춰 수정.
- **MusicDelta_Grunge 출처를 추측이 아니라 바이트 비교로 확정**: `data/songs/2/original.mid`와 Phase 0 T0-2 평가 파이프라인이 남긴 `data/t0-2-work/MusicDelta_Grunge.mid`를 `xxd`+`diff`로 비교해 완전히 동일함을 확인(CLAUDE.md §1-1 "모르는 정보는 지어내지 마라" — 기억에 의존한 추측이 아니라 실제 파일 비교로 검증). 이 트랙의 분류별 F-measure는 이미 `qa-evidence/T0-2/result_raw.json`에 측정돼 있었고(톰 0.33, 재현율 0.25), 사용자가 보고한 증상(초반 오탐, 중간 탐 누락으로 인한 "소리 사라짐")과 수치가 정확히 부합함을 확인했다.

## 사용자에게 전달할 내용
- 동기화 버그 자체는 T2-8에서 고쳤고, 판정 정밀도는 이번에 추가로 개선. **브라우저 탭을 오래 열어둔 상태라면 전체 새로고침 권장**(이 세션의 QA 중에도 Vite HMR이 최신 코드를 완전히 반영 못 하는 현상을 직접 겪어 전체 새로고침으로 해결한 전례가 있음).
- MusicDelta_Grunge는 사람이 만든 정확한 MIDI가 아니라 Phase 0에서 AI 모델이 실제 음원을 듣고 자동 채보한 테스트 데이터 — 정확한 노트 vs 실제 음 비교가 목적이면 이 곡 대신 사람이 만든 MIDI나 `drum_test_roundtrip.gp` 같은 깨끗한 샘플을 권장.
