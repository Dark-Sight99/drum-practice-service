# T2-10 계획 — Phase 2 게이트 3차 피드백

## 배경
T2-9 이후에도 의뢰인이 재보고: (1) 킷 점등은 판정선과 맞는데 소리는 그 뒤에 들림, (2) R/L이 잘 안 보임, (3) 스네어가 빠르게 R/L 번갈아 치는 게 맞는 건지 악보 없이는 확신 못함, (4) 내려오는 노트가 어느 부분을 치라는 건지 안 와닿음.

## 조사
`(4)`를 조사하다 `app/web/src/render/laneRenderer.ts`에 `lane.label`(HH/CR/SN/...)을 그리는 코드가 **전혀 없음**을 발견 — `intent/04-ui-ux.md` §3 와이어프레임에 `HH CR SN T1 T2 FT RD KK ← 레인 머리글`이 명시돼 있고 `intent/08-design.md` §4 타이포그래피 표에도 "레인 머리글 18px 700"이 지정돼 있었는데, T2-3(연습 화면 렌더러 최초 구현) 때 레인 구분선·노트·마디선·판정선만 구현하고 머리글 텍스트 자체를 빠뜨린 것으로 확인됨(구현 당시 QA에서도 발견 안 됨). 킷 일러스트에는 라벨이 있어 아래를 보면 알 수 있지만, 위에서 떨어지는 노트를 보는 동안엔 어느 레인이 무슨 피스인지 알 길이 없었음.

`(2)`는 현재 코드에서 R/L 폰트 최소 크기가 10px로 작게 설정돼 있었음을 확인 — 투명도(자동=50%)는 `intent/08-design.md` §3의 **의뢰인이 이미 결정한 수치**라 임의로 바꾸지 않고, 폰트 크기만 키움.

`(1)`(오디오-화면 잔여 간격)은 T2-8에서 이미 코드 대칭성(diff로 확정 가능한 수준)까지 맞춰둔 상태라 추가 코드 결함을 찾지 못함 — 실제 Web Audio 출력 하드웨어 지연(특히 블루투스 이어폰/스피커는 수십~수백 ms 지연이 흔함) 가능성과, 이전 수정이 브라우저에 완전히 반영 안 됐을 가능성(HMR 잔여 문제, 이 세션에서 직접 겪은 전례 있음) 둘 다 배제 못 해 의뢰인에게 직접 확인 요청.

`(3)`은 버그 리포트가 아니라 질문 — 코드 동작을 그대로 설명(필인 구간 판정 기준: 간격이 좁으면 교대, 넓으면 전부 기본손).

## 위험 작업 여부
레인 머리글 텍스트 추가·R/L 폰트 크기 조정 둘 다 노트의 시각(초) 계산을 안 건드리는 순수 Canvas 그리기 추가/조정이라 "오디오 타이밍·동기" 위험 작업 아님 — Codex 모드C 생략.

## 설계
- `render/laneRenderer.ts`: `LANE_HEADER_HEIGHT=20px` 영역을 캔버스 맨 위에 확보, 매 프레임 맨 마지막에(노트 위에 덮어 그려 항상 보이게) 배경 띠 + `LANES[i].label` 텍스트 그림. 배경색은 새 옵션 `laneHeaderBackgroundColor`(호출자가 `--bg` 전달).
- R/L 폰트: 최소 크기 10px→13px, `bold`로 변경(투명도 불변).

## 테스트 계획
전용 단위 테스트 없음(Canvas, jsdom 한계) — 실제 브라우저 수동 QA로 레인 머리글이 스크롤 중에도 항상 보이는지, R/L 글자가 더 잘 보이는지 확인.
