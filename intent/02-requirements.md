# 02. 요구사항 명세 (MVP)

표기: **[MVP]** 이번 범위 / **[확장]** 구조만 대비, 구현 안 함

## REQ-01 오디오 분리 [MVP]
- 입력: mp3, wav, m4a, flac (사용자 소장 음원)
- 처리: 처리 서버에서 Demucs로 `drums / bass / vocals / other` 분리. 결과를 곡 단위로 저장.
- [확장] 다른 악기 분리: 분리 모델을 인터페이스(`Separator`)로 추상화해 6트랙 모델 등으로 교체 가능하게.
- 수용 기준
  - 3~5분 곡 업로드 → 분리 완료 후 각 트랙 개별 재생 가능
  - 진행률/상태(대기·처리중·완료·실패) 표시. 실패 시 원인 메시지
  - 처리 시간 측정값을 로그에 기록

## REQ-02 드럼 MIDI 생성 [MVP]
세 가지 입력 경로가 모두 **동일한 내부 형식(DrumScore)**으로 수렴해야 한다.
| 경로 | 입력 | 방법 |
|---|---|---|
| A. 오디오 | REQ-01의 drums 트랙 | 드럼 채보 모델(ADT) |
| B. 종이 악보 | 사진(jpg/png), PDF | OMR → MusicXML → DrumScore |
| C. 디지털 악보 | MIDI(.mid), MusicXML(.musicxml/.mxl), Guitar Pro(.gp/.gp3~.gp5/.gpx) | 파서 |
- 최소 드럼 분류: 킥, 스네어, 하이햇(닫힘/열림), 탐(하이/미드/플로어), 크래시, 라이드. 모델이 구분 못 하는 분류는 상위 분류로 합친다(예: 탐 하나로).
- MIDI 내보내기(.mid, General MIDI 타악기 번호) 가능
- 수용 기준
  - 각 경로별 샘플 1개 이상으로 DrumScore 생성 성공
  - 경로 A: 기준곡(정답 MIDI 있는 곡)으로 분류별 F-measure 측정·기록 (목표치는 Phase 0 측정 후 설정)
  - 경로 B: 인식 실패/부분 인식 시에도 크래시 없이 "인식된 부분 + 편집 필요" 상태로 진입
  - 생성 결과는 원본 보존 + 편집본 별도 저장

## REQ-03 MIDI 간단 편집 [MVP]
- 노트 추가/삭제/이동(시간축 격자 스냅: 4·8·16분, 셋잇단), 킷 피스 변경, 셈여림(약/중/강 3단계)
- 실행 취소/다시 실행
- BPM·박자표 수정(곡 전체 1개 값. 중간 변속은 [확장])
- 수용 기준: 편집 → 저장 → 재로드 시 동일. 실행 취소 20단계 이상

## REQ-04 재생·BPM 변경·메트로놈 [MVP]
- 연습 BPM을 원곡 대비 50%~150% 범위로 설정(직접 BPM 입력 또는 %).
- 오디오 트랙은 **음정 유지** 상태로 속도 변경. MIDI·레인·메트로놈은 같은 BPM으로 동기화.
- 메트로놈: 켜기/끄기, 음량, 강박 강조, 박 단위(4·8분)
- 카운트인: 재생 전 1마디
- 구간 반복(A-B 루프): 마디 단위 지정
- 수용 기준
  - 60%·100%·130%에서 3분 재생 시 오디오와 메트로놈/레인 어긋남이 측정 허용치 이내(허용치는 Phase 0에서 측정 후 확정, 초기 목표 ±30ms)
  - 루프 경계에서 끊김·중복 클릭 없음

## REQ-05 트랙별 볼륨 [MVP]
- 트랙: 분리된 각 오디오 트랙, MIDI 드럼 소리(신스/샘플), 메트로놈
- 각 트랙 음량 슬라이더 + 음소거 + 솔로
- 프리셋 1개: "드럼 빼고 듣기(마이너스원)"
- 수용 기준: 조작 즉시(체감 지연 없이) 반영, 곡별 마지막 설정 기억

## REQ-06 드럼 연습 화면 [MVP]
- 상세는 `04-ui-ux.md`. 레인(노트 낙하) + 하단 드럼킷 점등.
- 수용 기준: 60fps 목표(측정), 폰 세로·가로/태블릿/PC 레이아웃 동작, 스크린샷 증거

## REQ-07 라이브러리 [MVP]
- 곡 목록(제목, 아티스트, 원곡 BPM, 입력 경로, 처리 상태)
- 연습 기록·진도 추적은 범위 외(의뢰인 결정, 2026-10-23)
- 업로드, 이름 변경, 삭제, 검색
- 곡별 저장: 원본 파일, 분리 트랙, DrumScore(원본/편집본), 연습 설정(BPM, 볼륨, 루프)
- 수용 기준: PC에서 올린 곡이 폰에서 목록에 보이고 재생됨

## REQ-08 로그인·기기 간 접근·다중 사용자 [MVP]
- 처리 서버(집 PC)가 데이터 저장소. 모든 기기는 로그인 후 접근.
- 범위(2026-10-23 확정): 대중 공개 아님, 비상업. 의뢰인 포함 소수 지인 **최대 6명**이 쓰는 비공개 서비스. 가입 화면 없음 — 관리자(의뢰인)가 계정을 직접 생성·정지. DB 스키마에 `user_id` 포함, 곡 라이브러리는 사용자별로 완전히 분리(REQ-07 참고).
- 외부 접속: Tailscale 개인 무료 플랜(최대 6명, 비상업)으로 확정 — 지인은 Tailscale 네트워크에 초대. Funnel(앱 없이 링크로 공개) 포함 여부는 참고 조사 중, 채택 여부는 별도 결정(`07-open-questions.md` Q-13)
- 수용 기준
  - 로그인 없이는 어떤 곡 데이터에도 접근 불가(테스트로 증명)
  - 사용자 A가 사용자 B의 곡 라이브러리·작업 상태에 접근 불가(테스트로 증명)
  - 관리자가 계정을 정지하면 해당 계정은 즉시 로그인 불가, 해당 기기의 오프라인 캐시는 다음 접속 시 삭제(REQ-09 참고)

## REQ-09 오프라인 연습 [MVP]
- 곡을 "오프라인 저장"하면 해당 기기에 오디오 트랙·DrumScore 캐시. 서버(PC)가 꺼져도 재생·연습 가능.
- 업로드·분리·변환은 온라인(서버 켜짐)에서만.
- 오프라인 유효기간(2026-10-23 확정): 서버에 마지막으로 접속해 세션을 재검증한 뒤 **30일까지** 오프라인 재생 허용. 30일 경과 시 서버 재접속·재검증 전까지 재생 차단.
- 로그아웃하거나 계정이 정지된 경우, 해당 기기가 다음에 서버에 접속하는 시점에 그 기기의 오프라인 캐시를 삭제한다.
- 수용 기준
  - 네트워크 차단 상태에서 저장된 곡 재생 성공(스크린샷)
  - 마지막 접속 30일 경과 시뮬레이션 → 재생 차단 확인
  - 계정 정지 후 재접속 시 해당 기기 오프라인 캐시 삭제 확인

## REQ-10 처리 작업 관리 [MVP]
- 무거운 작업(분리, 채보, OMR)은 서버 작업 큐에서 순차 처리. 브라우저를 닫아도 계속 진행.
- 다중 사용자 작업 큐(2026-10-23 확정): 여러 사용자의 작업을 하나의 큐에서 순서대로(FIFO) 처리. 각 사용자는 자기 자신의 작업 상태만 조회 가능(REQ-08 분리 원칙).
- 수용 기준: 작업 2개 연속 등록 시 순서대로 완료, 서버 재시작 후 미완료 작업 재개 또는 실패 표시. 사용자 A가 사용자 B의 작업 상태 조회 시도 시 차단(테스트로 증명)

## REQ-12 스티킹(RL) 표시·편집 [MVP]
배경: 의뢰인이 드럼을 배울 때 "필인은 어느 손부터 쳐야 깔끔한지" 같은 스티킹을 중요하게 배웠음.
- 각 노트에 손/발 정보: `R`(오른손), `L`(왼손), `RF`(오른발), `LF`(왼발), 미지정
- **표시**: 레인 노트 위에 R/L 글자, 하단 킷 점등도 손별 표식(예: 오른손 = 실선 테두리, 왼손 = 점선 테두리). 켜기/끄기 가능
- **편집**: 편집기에서 노트별 R/L 지정, 여러 노트 선택 후 "RLRL 교대" / "LRLR 교대" 일괄 적용
- **자동 추천** (오른손잡이 기본 규칙. 화면에 반드시 "추천" 표시):
  - 하이햇·라이드·크래시 → R, 킥 → RF, 하이햇 페달 → LF
  - 하이햇/라이드와 같은 박에 치는 스네어 → L
  - 연속 스네어·탐(필인) 구간 → 시작 손(기본 R, 설정 가능)부터 교대
  - 규칙은 코드 상수로 분리해 수정 가능하게. 규칙의 음악적 타당성은 의뢰인 검토로 확정(07 Q-11)
- 자동 결과보다 사용자가 직접 지정한 값이 항상 우선, 재분석해도 덮어쓰지 않음
- 원본 악보에 스티킹 표기가 있어도 OMR이 읽는다고 가정하지 않음(검증 전)
- 수용 기준: 필인 8노트에 일괄 교대 적용 → 레인·킷에 R/L 표시 스크린샷, 저장 후 재로드 동일

## REQ-11 직접 쳐서 판정 [확장 — 구현 안 함]
- 키보드 매핑/터치/전자드럼(USB-MIDI) 입력으로 타이밍 판정.
- 대비 사항: 연습 화면의 시간 기준(마스터 클록)을 하나로 두고, 입력 이벤트를 같은 클록으로 받을 수 있게 설계. 브라우저 오디오 지연 보정값 저장 필드만 확보.
