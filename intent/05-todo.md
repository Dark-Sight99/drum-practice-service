## Phase 0 — 환경 검증 스파이크 (코드는 버려도 됨)
**진행 규칙(가벼운 절차, 2026-10-23 확정)**: 필수 — 스파이크별 결과 보고(측정값·로그·실행 명령), `qa-evidence/T0-x/`에 증거 저장, 검증된 명령어는 `wiki/tools.md`에 기록. 생략 — 토론 로그, `work/<ID>/plan.md`, Codex 검수, 위키 아키텍처 문서. 정식 4단계 파이프라인(`06-pipeline.md`)은 Phase 1부터 전면 적용.

- [ ] T0-1 서버 후보 벤치마크: **윈도우(RTX 5060, CUDA 12.8+ PyTorch)만 지금 실측**. 같은 곡으로 Demucs 분리 시간 측정 → 표로 보고 (REQ-01). 벤치마크 스크립트와 설치 명령(맥/윈도우 공용)을 `qa-evidence/T0-1/`에 남겨 맥(M1) 입수 후 의뢰인이 직접 실행할 수 있게 한다. 맥 실측·최종 서버 PC 결정은 보류(Q-01)
- [ ] T0-2 ∥ 드럼 채보 모델 실행 확인: ADTOF 설치·실행, 출력 형식 확인. 정확도 측정은 **공개 데이터셋(MDB Drums, ENST-Drums 등 음원+정답 드럼 기록 쌍)** 사용 — 다운로드 전 라이선스·이용조건을 조사해 먼저 보고하고, 승인 후 다운로드. F-measure로 분류별 정확도 측정. 대안 모델 1개 이상 조사(라이선스 포함) (REQ-02)
- [ ] T0-3 ∥ OMR 확인: Audiveris CLI로 의뢰인 종이 드럼 악보 사진 2~3장(`data/samples/sheets/`, 선생님이 초보자용으로 고친 악보 — **OMR 인식 테스트 전용, 음원 채보 정답지로 사용하지 않음**) → MusicXML. 드럼 노트가 얼마나 살아남는지 보고 (REQ-02)
- [ ] T0-4 ∥ GP/MusicXML 가져오기: alphaTab으로 드럼 트랙 노트 추출 가능 여부 (REQ-02)
- [ ] T0-5 ∥ 음정 유지 속도 변경: 후보 2개를 60%/130%로 3분 재생, 메트로놈과 어긋남(ms) 측정, 폰 포함 (REQ-04)
- [ ] T0-6 라이선스 표 확정(03 문서 §4의 ⚠ 해소). 추가 확인:
  - PyMuPDF vs pypdfium2 라이선스 비교, 문제 없으면 pypdfium2 1순위 (Q-12)
  - Audiveris(AGPL-3.0)·ADTOF(CC BY-NC-SA 4.0)를 지인 포함 소수 사용자(최대 6명) 네트워크 서비스로 쓸 때의 라이선스 해석 — 법적 단정 금지, 근거와 함께 보고 (Q-14)
  - Tailscale Funnel이 개인 무료 플랜에 포함되는지 조사(참고용, 채택 여부는 별도 결정) (Q-13)
- [ ] **게이트**: 결과 보고 → 사용자: 서버 PC 결정, 모델 선택, 허용 오차 확정
