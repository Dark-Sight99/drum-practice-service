# 01. 비전

## 1. 상위 목표
**악보를 보는 데 어려움을 겪는 사람이 드럼 연습을 편하게 하도록 만든다. 첫 사용자는 의뢰인 본인.**

- 문제: 악기 연주는 좋아하지만 악보를 못 읽어 연습이 막힌다. 특히 드럼 악보(오선 위치 = 킷 피스)는 일반 악보와 읽는 법이 달라 진입장벽이 높다.
- 해결: 음원·디지털 악보 → 드럼 MIDI → "언제, 무엇을, 얼마나 세게" 치는지 레인과 드럼킷 점등으로 보여준다.
- 성공의 모습(본인 기준):
  1. ~~가진 종이 악보 사진을 올려 10분 안에 연습 가능한 상태로 만든다(인식 + 수정 포함).~~ **드롭(2026-10-26, 의뢰인 결정, 아래 "2026-10-26 갱신" 참고)**
  2. 음원을 올리면 드럼만 키우고 나머지는 줄여 들으며, 원곡보다 느린 BPM으로 따라 칠 수 있다.
  3. 실제 드럼 앞·PC 앞·이동 중 폰 어디서든 같은 라이브러리로 연습한다.

### 2026-10-26 갱신 — 종이 악보(OMR) 경로 드롭
Phase 3(음원으로 연습)를 몇 주간 실사용한 뒤 의뢰인이 직접 내린 판단(이 문서 §2 끝의 "실제 사용 후 '가장 불편한 것'이 다르면 갱신한다" 원칙 적용): **"연습하는데 음악 없이 드럼만 친다? 이거 아니거든"** — 음악 없이 악보(노트)만 보고 치는 연습은 애초에 원하는 경험이 아니었다는 걸 실제로 써보고서야 확인함. 의뢰인은 이미 연습하고 싶은 종이 악보를 다 폴더에 갖고 있지만, 그걸 OMR로 디지털화하는 대신 **그 곡의 음원을 구해 업로드하고 Phase 3의 자동 채보(REQ-01 Demucs 분리 + 드럼 채보 모델)로 만드는 쪽이 맞다**고 결론 — 음악과 함께 치는 경험 자체가 핵심 가치였음. REQ-02 경로 B(종이 악보→OMR)·Phase 4는 이 결정으로 드롭(`intent/02-requirements.md`, `intent/05-todo.md` 참고).

## 2. 핵심 변수 (가설)
**"자동 생성된 드럼 MIDI가 실제 연주와 얼마나 일치하는가."**
MIDI가 틀리면 틀린 걸 연습하게 되어 서비스 가치가 즉시 사라진다. 다른 기능(시각화, 메트로놈 등)은 기술적으로 확립된 영역이다.

따라서:
- 정확도를 **측정**한다 (Phase 0 / QA에 기준곡으로 F-measure 측정).
- 자동 결과를 사람이 **빠르게 고칠 수 있는** 편집기를 MVP에 넣는다.
- 변환 모듈은 인터페이스로 분리해 더 나은 모델이 나오면 교체한다.

> 이 가설은 기획 단계의 판단이다. 실제 사용 후 "가장 불편한 것"이 다르면 갱신한다.
